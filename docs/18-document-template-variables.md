# 18 · ตัวแปรในเอกสารต้นแบบ — คู่มือสำหรับผู้เขียนเอกสาร

คู่มือนี้เขียนให้ **คนที่แก้ไขไฟล์เอกสาร** ไม่ใช่คนเขียนโค้ด อ่านจบแล้วจะแก้ถ้อยคำ ย้ายช่องกรอก
หรือทำเอกสารฉบับใหม่เข้าระบบได้เองโดยไม่ต้องรอทีมพัฒนา

กลไกเบื้องหลัง (ทำไมต้องเป็น `.docx`, ตัวแปลงคืออะไร, เก็บเวอร์ชันอย่างไร) อยู่ที่
`docs/17-legal-document-rendering.md`

---

## 1 · หลักการสั้น ๆ

เอกสารต้นแบบเป็นไฟล์ **Word (`.docx`)** ธรรมดา ตรงไหนที่ต้องการให้ระบบเติมข้อมูลให้ ก็พิมพ์
**ชื่อตัวแปรในวงเล็บปีกกาสองชั้น** ลงไปตรงนั้น

```
ข้าพเจ้า {{signatory.fullName}} ตำแหน่ง {{signatory.position}}
ผู้มีอำนาจกระทำการแทน {{org.name}}
```

เวลาสร้างเอกสารจริง ระบบจะแทนที่ให้เป็น

```
ข้าพเจ้า นาย อนุชา พัฒนา ตำแหน่ง ผู้อำนวยการ
ผู้มีอำนาจกระทำการแทน กรมส่งเสริมการปกครองท้องถิ่น
```

**สิ่งที่ทำได้เองทั้งหมด** โดยไม่ต้องแก้โค้ด:

- ย้ายตัวแปรไปไว้ที่อื่นในเอกสาร
- ลบตัวแปรที่ไม่ต้องการออก
- ใช้ตัวแปรเดิมซ้ำหลายที่
- แก้ถ้อยคำ จัดหน้า เปลี่ยนตาราง เพิ่ม/ลบหน้า
- ทำเอกสารฉบับใหม่ที่หยิบตัวแปรชุดใดก็ได้จากรายการในข้อ 4

**สิ่งที่ต้องให้ทีมพัฒนาทำก่อน**: ใช้ชื่อตัวแปร**ใหม่ที่ยังไม่มีในรายการ** เพราะต้องมีคนบอกระบบ
ก่อนว่าชื่อนั้นต้องไปเอาข้อมูลมาจากไหน — ระบบจะปฏิเสธไฟล์ที่มีชื่อแปลกปลอมตอนอัปโหลด

## 2 · ข้อควรระวังตอนพิมพ์ตัวแปร

| เรื่อง | ทำ | ไม่ทำ |
|---|---|---|
| วงเล็บ | `{{org.name}}` สองชั้น | `{org.name}` ชั้นเดียว |
| ตัวพิมพ์ | ตรงตามรายการ เช่น `signatory.fullName` | `Signatory.FullName` |
| ช่องว่าง | ไม่มีช่องว่างในชื่อ | `{{org. name}}` |
| การจัดรูป | พิมพ์ชื่อให้จบในครั้งเดียว | พิมพ์ทีละตัวอักษรแล้วมาแก้ตรงกลาง |

**ข้อสุดท้ายสำคัญที่สุด** Word แบ่งข้อความเป็นชิ้นเล็ก ๆ ภายในไฟล์เวลาเราแก้ไปแก้มา ระบบรวม
ชิ้นเหล่านั้นกลับก่อนแทนที่อยู่แล้ว แต่วิธีที่ปลอดภัยที่สุดคือ **ลบชื่อเก่าทิ้งทั้งชุดแล้วพิมพ์ใหม่**
ไม่ใช่แก้แทรกกลางชื่อเดิม

จัดรูปแบบตัวอักษรของตัวแปรได้ตามปกติ (ตัวหนา ขีดเส้นใต้ สีอะไรก็ได้) ค่าที่เติมเข้าไปจะรับรูปแบบ
นั้นมาด้วย — เช่นในเอกสาร A0 ช่องที่อยู่ถูกขีดเส้นใต้แบบจุดไว้ ค่าที่เติมจึงมีเส้นจุดใต้ตัวหนังสือ

### ค่าที่ยังไม่เกิดขึ้น จะออกมาเป็นช่องว่าง

`{{approver.signature}}` ในเอกสารที่ยังไม่มีใครลงนาม จะกลายเป็น**ว่างเปล่า** ไม่ใช่คำว่า
"ไม่มี" หรือขีดกลาง — เพื่อให้ช่องลายมือชื่อที่ว่างสื่อว่ายังไม่มีการลงนาม ถ้าต้องการเส้นให้เซ็น
ให้วาดเส้นใต้หรือพิมพ์จุดไว้ในเอกสารเอง

## 3 · เอาไฟล์ที่แก้แล้วเข้าระบบ

```bash
curl -X POST https://bdi-api.thammasorn.org/api/admin/legal-documents/A0/versions \
  -H "x-admin-token: <ADMIN_API_TOKEN>" \
  -F "file=@A0.docx;type=application/vnd.openxmlformats-officedocument.wordprocessingml.document"
```

เปลี่ยน `A0` เป็นรหัสเอกสารที่ต้องการ (`A0` `A1` `A2` `A3` `A4`)

**ตอบ 201** = เผยแพร่แล้ว พร้อมรายชื่อตัวแปรที่ระบบอ่านเจอในไฟล์ — ใช้ตรวจว่าช่องที่ตั้งใจใส่ถูก
อ่านครบ ถ้าตัวไหนหาย มักเป็นเพราะพิมพ์ผิดหรือชื่อถูกแบ่งชิ้นตามข้อ 2

**ตอบ 400** = ไม่รับไฟล์ และ**ไม่มีอะไรเปลี่ยนในระบบ** เกิดได้สองกรณี:

- ใช้ชื่อตัวแปรที่ไม่มีในรายการ — ข้อความจะบอกชื่อที่ผิดและชื่อใกล้เคียงในกลุ่มเดียวกัน
- LibreOffice เปิดไฟล์ไม่ได้ หรือไฟล์ไม่ใช่ `.docx` จริง

เวอร์ชันก่อนหน้าจะกลายเป็น `SUPERSEDED` **คำขอที่ลงนามไปแล้วยังผูกกับเวอร์ชันเดิมของมัน** —
เอกสารที่หน่วยงานเซ็นไว้ไม่เปลี่ยนตามการแก้ครั้งใหม่

ดูรายการเอกสาร ทุกเวอร์ชัน และรายชื่อตัวแปรทั้งหมดพร้อมคำอธิบาย:

```bash
curl https://bdi-api.thammasorn.org/api/admin/legal-documents -H "x-admin-token: <ADMIN_API_TOKEN>"
```

## 5 · ทำเอกสารฉบับใหม่

เอกสาร A0–A4 มีแถวรออยู่ในระบบแล้ว (`legal.legal_document`) การทำฉบับใหม่ในรหัสที่มีอยู่คือ
อัปโหลดทับตามข้อ 3 เท่านั้น

ถ้าต้องการ**รหัสใหม่** (เช่น A5) หรือให้เอกสารฉบับนั้นเข้าไปอยู่ในขั้นตอนอนุมัติด้วย ต้องให้
ทีมพัฒนาเพิ่มแถวและกำหนดว่าเอกสารใช้กับ flow ไหน (`application_scope`) และต้องให้ผู้ใช้
เห็นชอบหรือไม่ — เพราะกระทบลำดับการลงนาม ไม่ใช่แค่เนื้อไฟล์

**ผนวก A1–A3 ตอนนี้ไม่มีตัวแปรเลยแม้ตัวเดียว** ใส่เพิ่มได้เลยถ้าต้องการ เช่นให้ทุกผนวกมี
`{{org.name}}` กับ `{{requestNumber}}` ที่หัวกระดาษ อัปโหลดทับแล้วใช้งานได้ทันที

> **ตัวแปรใช้ได้กับทุกฉบับ ไม่ใช่แค่ A0** ระบบดูจากไฟล์ว่ามี `{{...}}` หรือไม่ ไม่ได้ดูจาก
> รหัสเอกสาร ฉบับที่มีตัวแปรจะถูกสร้างใหม่ด้วยข้อมูลของแต่ละคำขอ ฉบับที่ไม่มีจะใช้ไฟล์กลาง
> ร่วมกันทุกหน่วยงาน (เร็วกว่าและไม่เปลืองที่เก็บ) เอาตัวแปรออกก็กลับไปใช้ไฟล์กลางเอง
> — ไม่ต้องแจ้งใครทั้งสองทาง

> **A1 A2 A3 ที่ใช้อยู่ยังมีร่องรอยการร่างติดมาด้วย** — ไฮไลต์ ขีดฆ่า และตัวอักษรสีแดง
> รวมหลายร้อยจุด (นับไว้ใน `docs/17-legal-document-rendering.md` §4) มาร์กเหล่านั้นจะปรากฏใน
> เอกสารที่หน่วยงานลงนาม ระบบไม่ได้ลบให้เพราะไม่ควรตัดสินแทนว่าข้อความที่ขีดฆ่าควรอยู่หรือไป
> เมื่อได้ฉบับสะอาดแล้วอัปโหลดทับได้เลย

## 6 · ตรวจงานก่อนใช้จริง

1. อัปโหลดขึ้น **checkout สำหรับทดสอบก่อน** ไม่ใช่ยิงขึ้น production ตรง ๆ
2. อ่านรายชื่อตัวแปรที่ตอบกลับมาใน 201 ว่าครบตามที่ใส่ไว้
3. เปิดคำขอที่รอลงนามอยู่ กดดูเอกสาร แล้วตรวจว่าค่าขึ้นถูกช่อง
4. ตรวจว่า**การแบ่งหน้าไม่เพี้ยน** — ค่าที่ยาวกว่าที่คาด (ชื่อหน่วยงานยาว ๆ) จะดันบรรทัดถัดไป
   ซึ่งเป็นเรื่องปกติและถูกต้อง แต่ควรดูว่าหน้าสุดท้ายไม่กลายเป็นหน้าที่มีบรรทัดเดียว

เลขหน้าในเอกสารจะเป็น **เลขอารบิก** แม้ต้นแบบตั้งเป็นเลขไทย — เป็นข้อจำกัดของตัวแปลง
อธิบายไว้ใน `docs/17-legal-document-rendering.md` §2
