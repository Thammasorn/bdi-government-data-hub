## 2. ฐานข้อมูล

`dataset.dataset_registration_metadata` (ระหว่างร่างและระหว่างตรวจ) และ
`dataset.dataset_metadata` (เมื่อชุดข้อมูลเข้าระบบแล้ว) **เปลี่ยนชุดคอลัมน์ทั้งตาราง**
จากฉบับ 2026-08-11 มาเป็นฉบับ 2026-08-16 — 35 คอลัมน์ ชื่อตรงกับ field_name ในชีท

- migration: `20260816150000_metadata_registration_form_2026_08_16`
- **ทำลายข้อมูลเดิม 16 คอลัมน์โดยไม่ backfill** เหตุผลอยู่ในหัวไฟล์ migration:
  คอลัมน์ใหม่ไม่ได้เปลี่ยนแค่ชื่อ แต่เปลี่ยนความหมายและชุดรหัส การเดาค่าให้เท่ากับ
  การกรอกแบบฟอร์มแทนหน่วยงาน ซึ่งเป็นเอกสารที่เขาต้องลงนาม
- ทุกคอลัมน์ nullable เพราะร่างบันทึกได้ทั้งที่ยังไม่ครบ — ความครบถ้วนบังคับตอนสร้าง PDF
  และตอนนำส่ง ด้วย `datasetSubmitSchema`
- เก็บ **รหัสของมาตรฐาน** ไม่ใช่ enum ที่ตั้งชื่อเอง (`"1"`, `"01"`, `"A"`, `"G0"`, `"a"`)
  ส่งต่อ DGA/DII ได้โดยไม่ต้องมีตารางแปลง และเพิ่มรหัสใหม่ได้โดยไม่ต้อง migrate
- `owner_org` เป็น FK ไปยัง `organization.organization` และ **คัดลอกมาจากหน่วยงานของคำขอ**
  ชีทเขียนว่า fixed เป็นหน่วยงานที่กรอกข้อมูล จึงไม่ใช่ช่องที่ผู้ใช้เลือก
- ตอนอนุมัติ `materialiseDataset()` คัดลอกทั้งแถวด้วย rest spread (ตัดเฉพาะ id/FK/audit)
  ไม่ไล่เขียนทีละช่อง — เพื่อให้คอลัมน์ที่เพิ่มทีหลังไม่เงียบหายตอนอนุมัติ

### ช่องที่ยังไม่มีคอลัมน์ในดีไซน์ — **ปิดคำถามแล้ว 2026-09-09**

เดิมชีท `conditions` สั่งว่า ถ้าเป็นข้อมูลส่วนบุคคลและอนุญาตให้ส่งต่อ (ข้อ 16.1 / 16.2 / 17)
ต้อง “ระบุหน่วยที่ให้ BDI ส่งต่อ” เพิ่มทั้งสามข้อ ดีไซน์ 2026-08-16 ไม่มีคอลัมน์ให้ จึงพักไว้ใน
`additional_metadata_json` เป็นคีย์ `transformedRawDataRecipients` ·
`transformedRawDataGdxRecipients` · `aggregatedDataRecipients` และค้างเป็นคำถามไว้

ชีทฉบับ **2026-09-09** ตอบคำถามนั้น: หมายเหตุเหลืออยู่ที่ **ข้อ 16.1 ข้อเดียว** และเปลี่ยนคำ
จาก “ระบุหน่วยงาน” เป็น “ระบุ**ระบบเชื่อมโยง**ข้อมูลที่อนุญาต” พร้อมยกขึ้นเป็นแถวของตัวเองใน
ชีทฟิลด์ มีชื่อคอลัมน์และขนาดครบ A4 ฉบับใหม่ก็มีบรรทัดให้ระบุใต้ข้อ 16.1 ที่เดียวเหมือนกัน

- ข้อ 16.1 → คอลัมน์จริง `allow_transformed_raw_data_sharing_specified_platforms` (1,000 ตัวอักษร)
  **ไม่บังคับกรอก** — ป้ายบอกความหมายของการเว้นว่างไว้เอง (“หากไม่ระบุถือว่าอนุญาตให้ส่งต่อได้ทุกระบบ”)
- ข้อ 16.2 และ 17 → **ไม่มีช่องให้ระบุอีกแล้ว** (BDI ยืนยัน 2026-09-10)
- `EXTRA_METADATA_KEYS` จึงว่าง แต่กลไกยังอยู่ และค่าที่คำขอเก่าเคยกรอกไว้ยังอยู่ใน
  `additional_metadata_json` ตามเดิม ไม่ได้ลบ

### ตัวเลือกอยู่ในฐานข้อมูล ไม่ใช่ในโค้ด — ตั้งแต่ 2026-09-13

รหัสกับป้ายภาษาไทยของทั้งสิบช่องที่เป็น `choice` (61 คู่) เป็นแถวใน
**`administration.dataset_choice`** ไม่ใช่ค่าคงที่ในโค้ดอีกต่อไป — การ์ด *"Choice master
data สำหรับ choice ในหน้า dataset registration"*

| สิ่งที่ต้องการ | ทำที่ไหน |
| --- | --- |
| แก้ป้าย · เรียงลำดับใหม่ · ปิดตัวเลือก · เพิ่มรหัส | `PATCH` / `POST /api/admin/dataset-choices` (ใช้ `x-admin-token`) **ไม่ต้อง deploy** |
| ดูรายการทั้งหมด รวมที่ปิดอยู่ | `GET /api/admin/dataset-choices` |
| หน้าเว็บอ่านจาก | `GET /api/dataset-choices` (ไม่ต้องล็อกอิน · เฉพาะที่เปิดอยู่ · เรียงแล้ว) |
| ค่าตั้งต้นของฐานข้อมูลใหม่ | `backend/src/lib/dataset-choices-defaults.ts` → `seed:masters` |

ข้อที่ต้องรู้:

- **`code` คือ id ตามที่ชีทแสดง** — `1 ข้อมูลระเบียน` เก็บเป็น `"1"`, `A ปี` เก็บเป็น `"A"`
- **ไม่มีการลบตัวเลือก** ปิดด้วย `isActive = false` แทน คำขอที่เลือกรหัสนั้นไว้แล้ว
  ยังนำส่งได้และยังพิมพ์ ✔ ได้ตามเดิม เพราะการตรวจค่าอ่านรหัสที่ปิดอยู่ด้วย
- **เพิ่มรหัสใน 13.3 กับ 14 ไม่ได้** ตารางเงื่อนไข (§4) ตัดสินตัวเลือกของสองช่องนี้เอง
  API จึงตอบ 409 พร้อมเหตุผล — ต้องแก้ `metadataRules()` ก่อน
- **เพิ่มรหัสแล้วช่องติ๊ก `{{tick.<ช่อง>.<รหัส>}}` ใช้ได้ทันที แต่แบบฟอร์ม A4 ไม่มีบรรทัด
  ให้มันเอง** ฝ่ายกฎหมายต้องแก้ .docx แล้วอัปโหลดเวอร์ชันใหม่ ดู `docs/18` §3
- **แก้แถวผ่าน psql หรือรัน `seed:masters` แล้วต้องรีสตาร์ต backend หรือเรียก
  `POST /api/admin/dataset-choices/refresh`** — คนละโปรเซสกับ API ค่าจึงยังไม่เข้า cache
  (แก้ผ่าน admin API ไม่ต้องทำ ระบบโหลดใหม่ให้เอง)
- `seed:masters` **ไม่ทับค่าที่แอดมินตั้งไว้** ป้าย ลำดับ และสถานะเปิด/ปิดอยู่ใน `create`
  เท่านั้น แบบเดียวกับ `isRequired` ของ `legal_document` — ไฟล์ค่าตั้งต้นจึงเป็น
  "ค่าเริ่มต้นของฐานข้อมูลใหม่" ไม่ใช่ "คำตอบสุดท้ายที่บังคับทุกฐานข้อมูล"
- ถ้าตารางว่าง ระบบ **ใช้ค่าตั้งต้นในโค้ดแทนพร้อมเตือนใน log** ไม่ล้ม — จำเป็น เพราะ
  `seed:masters` เองก็เผยแพร่ A4 ซึ่งตรวจชื่อช่องติ๊กกับรายการนี้ ถ้ารายการว่างแล้วล้ม
  สคริปต์ที่มีหน้าที่เติมตารางจะรันไม่ผ่าน `GET /health/ready` รายงานว่าใช้ชุดไหนอยู่

### ลำดับตัวเลือกในกล่องเลือก ไม่ใช่ลำดับรหัส

ตารางข้างบนบอก *ช่วงรหัส* ไม่ใช่ลำดับที่ผู้ใช้เห็นบนหน้าจอ ลำดับคือคอลัมน์ `display_order`
ในตาราง (เดิมคือ `CHOICE_ORDER` ใน `frontend/lib/dataset-form.ts` ซึ่งถูกลบไปแล้ว)
สองช่องที่ลำดับไม่ตรงกับรหัส

- **1.2 ประเด็น** — 01–07 แล้วปิดท้ายด้วย 99 “อื่น ๆ”
- **10 ความละเอียดเชิงภูมิศาสตร์** — ไล่จากหยาบไปละเอียด 01 “โลก” ถึง 11 “พิกัด” แล้วปิดท้าย
  ด้วย 00 “ไม่มี” · 98 “ไม่ทราบ” · 99 “อื่น ๆ” รหัส 00 อยู่ต้นรายการตามมาตรฐาน แต่ “ไม่มี”
  ไม่ใช่ระดับที่หยาบที่สุดของลำดับชั้น จึงไม่ควรเป็นตัวเลือกแรกที่ผู้ใช้เห็น

ก่อน 2026-09-07 ทั้งสองช่องเรียงตามที่ `Object.entries()` คืนมา ซึ่งยกคีย์ที่เป็นเลขจำนวนเต็ม
พอดี ("10" "11" "98" "99") ขึ้นก่อนคีย์ที่มีศูนย์นำเสมอ กล่อง “ประเด็น” จึงขึ้น “อื่น ๆ” เป็น
ตัวแรก และ “ความละเอียดเชิงภูมิศาสตร์” ขึ้น “องค์กรปกครองส่วนท้องถิ่น” ก่อน “โลก”

ช่องที่เหลือเรียงตามลำดับในชีท ซึ่งมี “อื่น ๆ” เป็นตัวสุดท้ายทุกช่องที่มีอยู่แล้ว

**ตัวเลือกที่เพิ่มใหม่ผ่าน API จะถูกต่อท้ายรายการ** ถ้าต้องการให้อยู่ตรงกลาง ต้อง `PATCH`
`displayOrder` ของมัน (และของตัวที่ต้องขยับ) เอง

## 4. ตารางเงื่อนไข (ชีท `conditions`)

อ่านจากซ้ายไปขวาแบบเดียวกับชีท: 13.1 → 13.2 → 13.3 → 14 → 15–17 → 18

1. **หมวด ก. ข้อมูลสาธารณะ** บังคับ 13.2 = ไม่มี, 13.3 = เปิดเผย, 14 = G0
   และบังคับ 15.1 ถึง 17 = อนุญาต ทั้งหมด ส่วนข้อ 18 ไม่ถาม
2. **ตัวเลือกของ 13.3 ขึ้นกับ 13.1** — ก. → เปิดเผย · ข. → ทั้งห้าระดับ (ถ้าเป็นข้อมูล
   ส่วนบุคคลจะตัด “เปิดเผย” ออก) · ค./ง. → ลับ · ลับมาก · ลับที่สุด
3. **ตัวเลือกของ 14 ขึ้นกับ 13.3** — เปิดเผย → G0 · เผยแพร่ภายในองค์กร → G0 หรือ G2 ·
   ลับขึ้นไป → G5
4. **ชุดข้อมูลที่เปิดเผยได้ทั้งฉบับ** (หมวด ก. หรือระดับชั้น “เปิดเผย”) ให้สิทธิ์ 15–17 ทุกข้อ
   อัตโนมัติ
5. **ระดับชั้น “เผยแพร่ภายในองค์กร” ที่ไม่มีข้อมูลส่วนบุคคล** บังคับ 16.1 · 16.2 · 17 = อนุญาต
   ส่วน 15.1 / 15.2 ผู้ใช้เลือกเอง
6. **15.2 ถามได้ต่อเมื่อ 15.1 = อนุญาต** ถ้าไม่ให้เก็บข้อมูลดิบต้นฉบับไว้ ก็ส่งต่อไม่ได้ (บังคับ N)
7. **ข้อมูลส่วนบุคคล + อนุญาตให้ส่งต่อ** เปิดข้อ 18 ให้ตอบ และถ้า **16.1** = อนุญาต จะเปิดช่อง
   “ระบุระบบเชื่อมโยงข้อมูลที่อนุญาต” ให้กรอกเพิ่ม (ไม่บังคับ) — ตั้งแต่ 2026-09-09 ข้อ 16.2
   กับ 17 ไม่มีช่องระบุเพิ่มอีกแล้ว
8. **10 = อื่น ๆ (รหัส 99)** ต้องระบุ `geo_coverage_other` เพิ่ม รูปแบบเดียวกับ 1.2 = 99

### บังคับที่ backend ไม่ใช่แค่ที่หน้าจอ

`normaliseMetadata()` ทำงานทุกครั้งก่อนเขียนฐานข้อมูล เติมค่าที่ถูกบังคับและล้างช่องที่
ไม่ต้องถาม ทดสอบแล้วด้วยการ PATCH ค่าที่ขัดกับชีทเข้าไปตรง ๆ (หมวดสาธารณะ + ไม่อนุญาต
ให้ส่งต่อ + ระดับชั้นลับที่สุด) ระบบเก็บเป็น เปิดเผย · G0 · อนุญาตทุกข้อ ตามชีท

### ค่าที่ถูกบังคับแล้วเงื่อนไขคลายออก

หน้าเว็บจะ **ล้างค่านั้นทิ้ง** ไม่ใช่ปล่อยค้างไว้ (เช่น เลือกหมวด ก. แล้วเปลี่ยนเป็น ค.)
เอกสารนี้คือหนังสือให้สิทธิ์ที่หน่วยงานลงนาม คำตอบที่ผู้ใช้ไม่เคยเลือกเองไม่ควรติดไปด้วย
