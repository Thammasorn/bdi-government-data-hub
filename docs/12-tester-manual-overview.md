# คู่มือผู้ทดสอบระบบ — ภาพรวมและการเข้าใช้งาน

เอกสารชุดนี้เขียนสำหรับ **ผู้ทดสอบระบบ** ที่ยังไม่เคยใช้ Government Datahub Platform มาก่อน
ไม่ต้องมีความรู้ทางเทคนิค ทำตามทีละข้อได้เลย ทุกหน้าจอในคู่มือเป็นภาพที่ถ่ายจากระบบจริง

| เล่ม | เนื้อหา | เขียนสำหรับ |
| --- | --- | --- |
| **เล่มนี้** | ภาพรวมระบบ · บัญชีทดสอบ · การเข้าสู่ระบบ · การแจ้งเตือน · ปัญหาที่พบบ่อย | ทุกคน |
| [เล่ม A](13-tester-manual-journey-a.md) | เจ้าหน้าที่ผู้ดูแลระบบสร้างหน่วยงานและเชิญผู้ใช้ | ผู้ดูแลระบบ (มีคำสั่งที่ต้องพิมพ์) |
| [เล่ม B](14-tester-manual-journey-b.md) | หน่วยงานลงทะเบียนตัวเองจนได้รับอนุมัติ | ผู้ทดสอบทั่วไป |
| [เล่ม C](15-tester-manual-journey-c.md) | หน่วยงานลงทะเบียนชุดข้อมูลจนได้รับอนุมัติ | ผู้ทดสอบทั่วไป |

> อ่านเล่มนี้ให้จบก่อน แล้วค่อยเริ่ม **เล่ม B** — เล่ม B กับ C ต่อกันเป็นเรื่องเดียว
> ส่วนเล่ม A เป็นสิ่งที่ผู้ดูแลระบบต้องทำให้ก่อนคุณจะมีบัญชีเข้าใช้งาน

## 1. ระบบนี้คืออะไร

Government Datahub Platform คือระบบกลางที่ให้ **หน่วยงานภาครัฐ** มาลงทะเบียนหน่วยงานของตัวเอง
แล้วนำ **ชุดข้อมูล** ที่หน่วยงานดูแลอยู่มาลงทะเบียนเข้าสู่ระบบกลาง โดยทุกอย่างต้องผ่าน
การตรวจสอบและอนุมัติเป็นขั้น ๆ

![หน้าแรกของระบบสำหรับผู้ที่ยังไม่ได้เข้าสู่ระบบ](images/manual/00-landing.png)

*หน้าแรกก่อนเข้าสู่ระบบ — กดปุ่ม **เข้าสู่ระบบ** ที่มุมขวาบนเพื่อเริ่ม*

### เรื่องราวทั้งหมดมีสามตอน

```
ตอนที่ A  ผู้ดูแลระบบสร้าง "หน่วยงาน" ไว้ล่วงหน้า แล้วส่งคำเชิญไปที่อีเมลของคุณ
              ↓
ตอนที่ B  คุณเปิดใช้งานบัญชี → กรอกแบบฟอร์มลงทะเบียนหน่วยงาน → ผ่านการตรวจ 3 ด่าน
              ↓  หน่วยงานเปิดใช้งานแล้ว
ตอนที่ C  คุณลงทะเบียนชุดข้อมูล → ผ่านการตรวจ 4–5 ด่าน → ได้เอกสารอนุมัติ
```

### คนที่เกี่ยวข้องมีใครบ้าง

| บทบาท | ทำอะไร | อยู่ฝั่งไหน |
| --- | --- | --- |
| **ผู้ดำเนินการของหน่วยงาน** | กรอกแบบฟอร์มลงทะเบียนหน่วยงาน และกรอกคำขอลงทะเบียนชุดข้อมูล | หน่วยงานของคุณ |
| **ผู้มีอำนาจกระทำการแทน** | ตรวจเอกสารแล้ว "เห็นชอบและลงนาม" แทนหน่วยงาน | หน่วยงานของคุณ |
| **เจ้าหน้าที่ BDI** | ตรวจสอบความถูกต้อง ส่งกลับให้แก้ หรือส่งต่อไปด่านถัดไป | BDI |
| **ผู้เชี่ยวชาญข้อมูล BDI** | ตรวจเนื้อหาชุดข้อมูลเฉพาะรายการที่ถูกมอบหมาย | BDI |
| **ผู้อนุมัติ BDI** | ลงนามอนุมัติขั้นสุดท้าย | BDI |

> **หนึ่งหน่วยงานมีผู้ดำเนินการได้ทีละหนึ่งคน และมีผู้มีอำนาจกระทำการแทนได้ทีละหนึ่งคน**
> ถ้าจะเปลี่ยนตัว ต้องให้ผู้ดูแลระบบยกเลิกสิทธิ์ของคนเดิมก่อน

## 2. ก่อนเริ่มทดสอบ ต้องมีอะไรบ้าง

ขอสามอย่างนี้จาก **ผู้ดูแลระบบ** ก่อนเริ่ม

1. **ที่อยู่เว็บของระบบทดสอบ** — เช่น `http://localhost:3400` หรือ `https://bdi.thammasorn.org`
   (คู่มือนี้ใช้ภาพจากระบบที่อยู่ที่ `http://localhost:3400`)
2. **อีเมลที่ได้รับคำเชิญ** พร้อมรหัสผ่านที่คุณจะตั้งเอง
3. **ช่องทางรับรหัส OTP** — ดูข้อ 4 ว่าระบบทดสอบเครื่องนั้นส่งอีเมลจริงหรือไม่

### บัญชีตัวอย่างที่มีอยู่แล้วในระบบทดสอบ

ถ้าผู้ดูแลระบบใส่ข้อมูลตัวอย่าง (seed) ไว้ จะมีบัญชีเหล่านี้ให้ใช้ทันที
**รหัสผ่านเหมือนกันทุกบัญชี: `bdi12345`**

| อีเมล | บทบาท |
| --- | --- |
| `officer@bdi.or.th` | เจ้าหน้าที่ BDI — ตรวจสอบทุกคำขอในระบบ |
| `approver@bdi.or.th` | ผู้อนุมัติ BDI — ลงนามขั้นสุดท้าย |
| `specialist@bdi.or.th` | ผู้เชี่ยวชาญข้อมูล BDI |
| `user@nso.go.th` | ผู้ดำเนินการของสำนักงานสถิติแห่งชาติ (หน่วยงานเปิดใช้งานแล้ว) |
| `director@nso.go.th` | ผู้มีอำนาจกระทำการแทนของสำนักงานสถิติแห่งชาติ |
| `newbie@moi.go.th` | ผู้ที่เพิ่งรับคำเชิญ ยังไม่ได้กรอกหน่วยงาน |

> ระหว่างทดสอบคุณจะต้อง **สลับบัญชีบ่อยมาก** (คนกรอก → เจ้าหน้าที่ → ผู้ลงนาม → ผู้อนุมัติ)
> แนะนำให้เปิด **หน้าต่างไม่ระบุตัวตน (Incognito) แยกหนึ่งหน้าต่างต่อหนึ่งบทบาท**
> จะได้ไม่ต้องออกจากระบบแล้วเข้าใหม่ตลอด

## 3. การเข้าสู่ระบบ

ระบบนี้ **ไม่มีการสมัครสมาชิกเอง** ทุกบัญชีเกิดจากคำเชิญของผู้ดูแลระบบเท่านั้น

เข้าสู่ระบบได้สองทาง

### ทางที่ 1 — อีเมล + รหัสผ่าน + รหัส OTP

![หน้าเข้าสู่ระบบ](images/manual/a06-login.png)

1. กรอก **อีเมล** และ **รหัสผ่าน** แล้วกด **เข้าสู่ระบบ**
2. ระบบยังไม่ให้เข้า แต่จะส่ง **รหัส 6 หลัก** ไปที่อีเมลนั้นก่อน

![หน้ากรอกรหัส OTP 6 หลัก](images/manual/a07-login-otp.png)

3. กรอกรหัส 6 หลักลงในช่อง (วางทั้งชุดทีเดียวก็ได้) ครบ 6 หลักแล้วระบบพาเข้าเองอัตโนมัติ
   **ไม่ต้องกดปุ่มใด ๆ**

กติกาของรหัส OTP

- ใช้ได้ **10 นาที**
- กรอกผิดได้ **5 ครั้ง** เกินกว่านั้นต้องกดขอรหัสใหม่
- ปุ่มขอรหัสใหม่ต้องรอ **60 วินาที** (หน้าจอจะนับถอยหลังให้ดู)

### ทางที่ 2 — ThaiD

กดปุ่ม **เข้าสู่ระบบด้วย ThaiD** แล้วยืนยันตัวตนด้วยเลขบัตรใบเดิมที่ใช้ตอนเปิดใช้งานบัญชี
ระบบจะจับคู่บัญชีให้เอง ไม่ต้องกรอกอีเมลหรือรหัสผ่าน และ**ไม่ต้องใช้ OTP**

> ปุ่มนี้ใช้ได้เฉพาะบัญชีที่เปิดใช้งานด้วย ThaiD ไปแล้ว
> ถ้าเครื่องทดสอบยังไม่ได้ตั้งค่าการเชื่อมต่อ ThaiD กดแล้วจะขึ้นข้อความว่ายังไม่ได้ตั้งค่า

### ออกจากระบบ

กดชื่อของคุณที่มุมขวาบน → **ออกจากระบบ**

## 4. เรื่องอีเมลและรหัส OTP บนเครื่องทดสอบ

ระบบส่งอีเมลรวม 15 แบบ (คำเชิญ · รหัส OTP · แจ้งผลการตรวจสอบ ฯลฯ) แต่**เครื่องทดสอบ
ส่วนใหญ่ตั้งค่าให้ไม่ส่งอีเมลจริง** เพื่อไม่ให้ไปรบกวนกล่องจดหมายของใคร

| เครื่องทดสอบตั้งค่าแบบไหน | คุณจะได้รหัส OTP และลิงก์คำเชิญจากที่ไหน |
| --- | --- |
| **ส่งอีเมลจริง** | เปิดกล่องจดหมายตามปกติ (ดูโฟลเดอร์ Spam/Promotions ด้วย) |
| **ไม่ส่งจริง** (ค่าปกติของเครื่องทดสอบ) | **ขอจากผู้ดูแลระบบ** — ระบบพิมพ์รหัสไว้ในบันทึกการทำงานของเครื่อง |

คำสั่งสำหรับผู้ดูแลระบบ (พิมพ์ที่เครื่องที่ติดตั้งระบบ ในโฟลเดอร์ของ checkout นั้น)

```bash
docker compose logs backend --tail 20 | grep 'รหัส OTP'          # รหัส OTP ล่าสุด
docker compose logs backend --tail 200 | grep 'ลิงก์:'            # ลิงก์คำเชิญล่าสุด
docker compose logs delivery-worker --tail 40 | grep -E 'ถึง:|เรื่อง:'   # อีเมลแจ้งเตือนที่ส่งออก
```

## 5. การแจ้งเตือนในระบบ

รูประฆังมุมขวาบนมีตัวเลขบอกจำนวนเรื่องที่ยังไม่อ่าน กดแล้วเห็นรายการล่าสุด
**กดที่หัวข้อเรื่องเพื่อกระโดดไปที่คำขอนั้นได้ทันที**

![กระดิ่งแจ้งเตือนพร้อมรายการที่ยังไม่อ่าน](images/manual/b16-notification-bell.png)

> การแจ้งเตือนไม่ได้อัปเดตแบบเรียลไทม์ตามที่ออกแบบไว้ — ระบบดึงข้อมูลใหม่ตอนเปิดหน้าหรือ
> เปลี่ยนหน้าเท่านั้น **ถ้าเพิ่งมีคนกดอนุมัติ ให้กดรีเฟรชหน้าหนึ่งครั้ง**

## 6. สิ่งที่ควรรู้ก่อนกรอกแบบฟอร์มทุกชนิด

1. **ปุ่ม `บันทึกแบบร่าง` ใช้ได้ตลอดเวลา** ปิดเบราว์เซอร์แล้วกลับมาข้อมูลยังอยู่
   และไม่บังคับว่าต้องกรอกครบ
2. **ปุ่ม `ตรวจสอบและสร้าง PDF` คือขั้นตรวจความครบถ้วน** ถ้ายังไม่ครบ ระบบจะขึ้นข้อความ
   สีแดงใต้ช่องที่มีปัญหา พร้อมบอกว่าต้องแก้อย่างไร ไม่ใช่แค่บอกว่าผิด
3. **เมื่อกด "นำส่ง" แล้วแก้ไขไม่ได้อีก** จนกว่าผู้ตรวจสอบจะส่งกลับมาให้แก้
4. **ช่องที่มีเครื่องหมาย `*` คือช่องบังคับ**
5. แถบด้านซ้ายของฟอร์มบอกว่าแต่ละส่วน **กรอกครบแล้ว** หรือ **ยังไม่ครบ** ใช้ตรวจความคืบหน้าได้

### กติกาของข้อมูลบางช่องที่มักกรอกผิด

| ช่อง | กติกา | ตัวอย่างที่ผ่าน |
| --- | --- | --- |
| รหัสผ่าน | อย่างน้อย 8 ตัว มีทั้งตัวอักษรและตัวเลข | `bdi12345` |
| เบอร์โทรศัพท์ | ขึ้นต้นด้วย `0` และมี 9–10 หลัก | `0812345678` |
| เลขบัตรประชาชน | 13 หลัก และต้องผ่านการตรวจหลักสุดท้าย (เลขมั่วไม่ผ่าน) | `1101700207994` |
| ไฟล์แนบของหน่วยงาน | PDF หรือ JPG ไม่เกิน 10 MB | — |
| พจนานุกรมข้อมูล | PDF, XLSX หรือ CSV ไม่เกิน 10 MB | — |
| ตัวอย่างข้อมูล | CSV, XLSX หรือ JSON ไม่เกิน 10 MB | — |

## 7. ปัญหาที่พบบ่อย

| อาการ | สาเหตุที่พบบ่อยที่สุด | ทำอย่างไร |
| --- | --- | --- |
| กรอกรหัสผ่านถูกแล้วแต่ไม่เข้า | ยังไม่ได้กรอก OTP | ดูข้อ 3–4 |
| ไม่ได้รับรหัส OTP ในอีเมล | เครื่องทดสอบไม่ได้ส่งอีเมลจริง | ขอรหัสจากผู้ดูแลระบบ (ข้อ 4) |
| กดปุ่ม ThaiD แล้วขึ้นว่ายังไม่ได้ตั้งค่า | เครื่องทดสอบยังไม่ได้ใส่ข้อมูลเชื่อมต่อ ThaiD | แจ้งผู้ดูแลระบบ |
| เปิดลิงก์คำเชิญแล้วขึ้นว่าถูกใช้ไปแล้ว | ลิงก์ใช้ได้ครั้งเดียว | ขอลิงก์ใหม่จากผู้ดูแลระบบ |
| เปิดลิงก์คำเชิญแล้วขึ้นว่าถูกยกเลิกแล้ว | ยืนยันตัวตน ThaiD ด้วยเลขบัตรที่ไม่ตรงกับที่บันทึกไว้ | ขอลิงก์ใหม่ และตรวจเลขบัตรกับเจ้าหน้าที่ |
| กดปุ่ม "ลงทะเบียนชุดข้อมูล" ไม่ได้ (ปุ่มจาง) | หน่วยงานยังไม่ผ่านการอนุมัติ หรือยังไม่มีผู้ลงนาม | ข้อความใต้ปุ่มบอกว่าติดอะไร ดูเล่ม C ข้อ 1 |
| หน้าจอค้างที่วงกลมหมุน | เครื่องทดสอบกำลังคอมไพล์หน้านั้นครั้งแรก | รอสักครู่แล้วกดรีเฟรช |
| กดอนุมัติแล้วสถานะไม่เปลี่ยน | หน้าจอยังเป็นข้อมูลเก่า | กดรีเฟรชหน้าหนึ่งครั้ง |

## 8. สิ่งที่ยังไม่ได้ทำในเฟสนี้ (ไม่ใช่ข้อผิดพลาด)

ระหว่างทดสอบคุณอาจสงสัยว่าทำไมไม่มีสิ่งเหล่านี้ — เป็นเรื่องที่ตั้งใจยังไม่ทำ

- **ไม่มีหน้าจอสำหรับผู้ดูแลระบบ** การสร้างหน่วยงานและการเชิญผู้ใช้ทำผ่านคำสั่งเท่านั้น (เล่ม A)
- **ไม่มีปุ่มเปลี่ยนรหัสผ่าน** และไม่มีปุ่ม "ลืมรหัสผ่าน"
- **การลงนามไม่ใช่ลายเซ็นดิจิทัลจริง** เป็นการกดยืนยันแล้วระบบบันทึกชื่อกับเวลาไว้
- **นิติกร BDI ยังไม่มีหน้าจอของตัวเอง** มีไว้ให้บทบาทครบตามการออกแบบ
- **ยังไม่มีการเชื่อมต่อกับระบบ DII และ Jira**
