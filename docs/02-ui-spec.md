## 1. Design tokens

### 1.1 สีแบรนด์

| Token | Hex | ที่มา | ใช้กับ |
| --- | --- | --- | --- |
| `--brand-navy` | `#192768` | swatch ล่างซ้าย + ตัวโลโก้ | สีหลัก, header, หัวข้อ, ปุ่มหลัก |
| `--brand-blue` | `#364B96` | swatch บนซ้าย | สีรอง, ลิงก์, chart |

### 1.4 ตัวอักษร

ใช้เฉพาะฟอนต์ที่อยู่ในชุด CI — โหลดจากเครื่อง ไม่เรียก Google Fonts (ทำงานหลัง firewall ได้)

| บทบาท | ฟอนต์ | น้ำหนัก | เหตุผล |
| --- | --- | --- | --- |
| หัวข้อ / display | **Prompt** | 500, 600, 700 | เป็น geometric sans ที่เข้ากับรูปทรงโลโก้ BD รองรับไทย+ละติน |
| เนื้อความ / UI | **Sarabun** | 400, 500, 600 | อ่านไทยยาว ๆ ได้สบายตากว่า Prompt มาก |

สเกล (rem): `12 · 14 · 16 · 18 · 20 · 24 · 30 · 36 · 48`
line-height เนื้อความไทย **1.7** (สูงกว่าปกติเพราะสระบน-ล่างของไทยต้องการที่หายใจ)

### 1.5 ระยะและรูปทรง

- Spacing scale 4px: `4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64`
- Radius: `sm 6px` · `md 10px` · `lg 16px` · `pill 999px`
  ทรง pill มาจาก support element ของ CI ที่เป็นแคปซูลปลายมน
- Shadow: บาง ๆ ชั้นเดียว `0 1px 2px rgba(20,26,51,.06), 0 4px 12px rgba(20,26,51,.05)`
  งานราชการควรดูเรียบ ไม่ลอยฟู

### 1.6 โลโก้

ไฟล์ต้นฉบับอยู่ที่ `assets/theme_ci_design/LOGO/` — `SVG/` สำหรับงานเว็บ, `1x 2x 3x/` เป็น PNG
ชื่อไฟล์อ่านได้ตรงตัว: `rec-` คือแบบแนวนอน (เครื่องหมาย + ชื่อสถาบัน), `sqr-` คือเครื่องหมาย
B) อย่างเดียว, ลงท้าย `-th` / `-th-en` คือชื่อสถาบันภาษาไทย / ไทยคู่อังกฤษ,
`-white` และ `-for-dark-bg` คือเวอร์ชันสำหรับพื้นเข้ม

ในโค้ดไม่ได้อ้างไฟล์เหล่านี้ตรง ๆ แต่คัด path มาไว้ในที่เดียวต่อช่องทาง:

| ที่ใช้ | มาจาก | รูปแบบ |
| --- | --- | --- |
| เว็บ (`frontend/components/brand/Logo.tsx`) | `sqr-logo-normal.svg`, `rec-logo-normal-th.svg` | inline SVG, สีกรมท่าเป็น `currentColor` + จุดคอรัลแยก class |
| favicon (`frontend/app/icon.svg`, `apple-icon.png`) | `sqr-logo-for-dark-bg.svg` | เครื่องหมายบนพื้นกรมท่า |
| PDF (`backend/src/assets/brand/bdi-mark.png`) | `3x/sqr-logo-normal@3x.png` | PNG ครอปขอบ — PDFKit ฝัง SVG ไม่ได้ |
| อีเมล (`backend/src/assets/brand/bdi-logo.png`) | `3x/rec-logo-normal-th@3x.png` | PNG แนบไปกับอีเมลแล้วอ้างด้วย `cid:` |

**viewBox ของ inline SVG ถูกครอปให้พอดีตัวโลโก้** ต้นฉบับเผื่อ clear space ไว้รอบละ ~36 หน่วย
ถ้าเก็บไว้ `h-7` ที่ผู้เรียกสั่งจะเป็นความสูงของกรอบ ไม่ใช่ของโลโก้ ระยะห่างรอบโลโก้จึงคุมด้วย
`gap`/`padding` ของ layout แทน

### 1.7 Support element

CI ให้ลาย **dot grid** และ **แคปซูลปลายมน** มาใช้ตกแต่ง นำมาใช้เป็น:

- ลายจุดจาง ๆ มุมขวาบนของ hero และหน้า auth (opacity ≤ 0.10)
- แถบ gradient coral→navy สูง 3px คาดบนสุดของ header
- ห้ามใช้ลายจุดหลังตาราง/ฟอร์ม เพราะรบกวนการอ่าน

## 2. โครงหน้าจอ

```
┌──────────────────────────────────────────────────┐
│ ▔▔▔ แถบ gradient 3px ▔▔▔                          │
│ [BD โลโก้] Government Datahub    [เมนู] [ผู้ใช้ ▾] │  header 64px sticky
├──────────────────────────────────────────────────┤
│                                                  │
│   เนื้อหา  max-width 1200px  (ฟอร์ม 760px)        │
│                                                  │
├──────────────────────────────────────────────────┤
│ โลโก้ · ลิงก์ · © BDI                             │  footer
└──────────────────────────────────────────────────┘
```

เมนูใน header เปลี่ยนตาม role:

| Role | เมนูที่เห็น |
| --- | --- |
| `ORG_USER` ที่ยังไม่มีหน่วยงาน | *(ไม่มีเมนู — เห็นแต่ปุ่มสร้างหน่วยงานกลางจอ)* |
| `ORG_USER` ที่มีหน่วยงานแล้ว | หน้าแรก · หน่วยงานของฉัน · ชุดข้อมูล |
| `ORG_APPROVER` ที่ผูกหน่วยงานแล้ว | หน้าแรก · หน่วยงานของฉัน · ชุดข้อมูล |
| `ORG_APPROVER` ที่ยังไม่ผูกหน่วยงาน | หน้าแรก · ชุดข้อมูล |
| `BDI_OFFICER` | หน่วยงาน · ชุดข้อมูล |
| `BDI_FINAL_APPROVER` | หน่วยงาน · ชุดข้อมูล · รอลงนาม |
| `BDI_DATASET_SPECIALIST` (อย่างเดียว) | ชุดข้อมูลที่ได้รับมอบหมาย |

ขวาสุดของ header มี **กระดิ่งแจ้งเตือน** สำหรับผู้ที่ล็อกอินแล้วทุก role
จำนวนที่ยังไม่อ่านแสดงเป็นตัวเลขบนวงกลม coral (ไม่ใช้จุดสีเปล่า ๆ เพราะสื่อความหมายไม่ได้)
ดึงข้อมูลใหม่ตอนโหลดหน้าและตอนเปลี่ยนหน้าเท่านั้น — สเปกระบุว่าไม่ต้อง real time

### 4.1 B1 — Empty state (สเปกเน้นเป็นพิเศษ)

```
รายการข้อมูลที่รออนุมัติ  (N รายการ)         ← อยู่บนสุดเสมอ ตามสเปก

                                              ปิดท้ายด้วยลิงก์ไป /datasets
```

- **สอง section ตามสเปก** — รายการที่รออนุมัติอยู่บนสุดเสมอ ตามด้วยชุดข้อมูลที่เหลือ
  ของหน่วยงาน คำขอหนึ่งใบปรากฏใน section เดียว ไม่แสดงซ้ำสองที่
- "รออนุมัติ" คือสี่สถานะที่ยังเดินอยู่ในสายพาน (`PENDING_*`) — ดู `PENDING_DATASET_STATUSES`
  ใน `frontend/lib/status.ts`
- ทั้งสอง section เรียงตามวันเวลาที่ส่งคำขอ **ใหม่ → เก่า** ทิศทางเดียวกับตารางในหน้า
  `/datasets` เพื่อไม่ให้ผู้ใช้ต้องอ่านสองแบบในจอเดียว (ร่างที่ยังไม่ส่งใช้วันที่สร้างแทน)
- แต่ละแถวมีครบตามสเปก: ชื่อชุดข้อมูล · สถานะ · วันเวลาที่นำเข้ามา · วันเวลาที่อัปเดตล่าสุด
  · ปุ่ม view (`ดูรายละเอียด`) และ download (`ดาวน์โหลด`)
- ใต้ badge มีข้อความบอก **ด่านที่คำขอค้างอยู่ พร้อมเลขขั้นและขั้นต่อไป** ("ขั้นที่ 2 จาก 4 · รอผู้มีอำนาจของหน่วยงานลงนาม") — ชื่อสถานะอย่างเดียวไม่บอกว่าใครถืออยู่ และด่านอย่างเดียวไม่บอกว่าเหลืออีกไกลแค่ไหน
- คำขอที่ยังไม่มี PDF (ฉบับร่างที่ยังไม่กดสร้างแบบฟอร์ม) ปุ่มดาวน์โหลด **ยังอยู่แต่กดไม่ได้**
  พร้อม tooltip บอกว่าติดอะไร ตามหลักข้อ 6 ท้ายเอกสาร
- คำขอที่ค้างเกิน 7 วันขึ้นป้าย `รอมาแล้ว N วัน` — เฉพาะรายการที่ยังรออยู่จริง
  ไม่ขึ้นกับรายการที่อนุมัติหรือไม่อนุมัติไปแล้ว
- ผู้มีอำนาจกระทำการแทนได้การ์ด coral เพิ่มหนึ่งใบเมื่อมีคำขอสถานะ `PENDING_ORG_APPROVER`
  เพราะเป็นคนเดียวที่กดต่อได้ที่ด่านนั้น — ไม่ควรให้จมอยู่ในรายการรวม
- ผู้มีอำนาจที่ถูกเชิญมาทีหลังยังไม่มี `organizationId` แต่เห็นคำขอผ่าน `signatoryEmail`
  จึงต้องได้หน้าแรกแบบเดียวกัน ไม่ใช่หน้าชวนสร้างหน่วยงาน

### 4.2 B2 — ฟอร์มสร้างหน่วยงาน

- ซ้าย: stepper 3 ขั้น แสดงว่าส่วนไหนกรอกครบแล้ว (sticky)
- ขวา: การ์ดสามใบเรียงลง แต่ละใบมีหัวข้อและคำอธิบายสั้น
- ตรวจข้อมูลตอน blur ไม่ใช่ตอนพิมพ์ (ไม่ด่าผู้ใช้ระหว่างกำลังพิมพ์)
- error แสดงใต้ช่อง + ขอบแดง; ตอนกดบันทึกแล้วมีที่ผิด → **toast** ตามสเปก
  แล้วเลื่อนจอไปที่ช่องแรกที่ผิด
- อัปโหลดไฟล์: drag & drop, แสดงชื่อ+ขนาด, ลบได้, จำกัด pdf/jpg ≤ 10MB
- ปุ่มล่าง: `บันทึกแบบร่าง` (secondary) และ `ตรวจสอบและสร้าง PDF` (primary)
- จังหวัด→อำเภอ→ตำบล เป็น dropdown ที่กรองต่อกันเป็นชั้น

## 5. หลักการที่ยึดตลอด

1. **ไทยมาก่อน** — UI ภาษาไทยทั้งหมด ใช้ line-height สูง เผื่อวรรณยุกต์
2. **ปุ่มหลักหนึ่งเดียวต่อหน้า** — ที่เหลือเป็น secondary/ghost
3. **ไม่ใช้สีสื่อความหมายเพียงอย่างเดียว** — badge มีทั้งสีและข้อความเสมอ
4. **โฟกัสเห็นชัด** — `outline: 2px solid var(--brand-blue); outline-offset: 2px`
   งานภาครัฐต้องใช้คีย์บอร์ดล้วนได้
5. **แตะได้ ≥ 44px** บนมือถือ
6. **ข้อความ error บอกวิธีแก้** ไม่ใช่แค่บอกว่าผิด
