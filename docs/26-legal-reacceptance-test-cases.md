# 26 — การลงนามเอกสารกฎหมายเวอร์ชันใหม่: กรณีทดสอบ

Card "[Enhance] Legal Document Management" · branch `enhance-legal-document-management-2`

เอกสารนี้เขียนให้ทดสอบด้วยมือจากหน้าเว็บ **เรียงตามลำดับเวลา บนฐานข้อมูลชุดเดียว** — ชุดหลังใช้ผลของชุดก่อน
ถ้าต้องเริ่มใหม่ ให้รันขั้น "เตรียมข้อมูล" อีกครั้ง

## 1. เตรียมข้อมูล

```bash
docker compose exec backend npm run seed:masters          # ครั้งแรกของฐานข้อมูลเท่านั้น
docker compose exec backend npm run seed:demo             # ล้างข้อมูลทั้งหมดแล้วสร้างข้อมูลตัวอย่าง
docker compose exec backend npm run seed:legal-reacceptance -- --stage=baseline
docker compose restart backend
```

`seed:legal-reacceptance` (`backend/src/scripts/seed-legal-reacceptance.ts`) มีสองแบบ

| แบบ | ใช้เมื่อ | ผลที่ได้ |
|---|---|---|
| `--stage=baseline` | **ทดสอบตามเอกสารนี้** | หน่วยงาน ACTIVE ทั้งสองแห่งลงนามเวอร์ชันที่ใช้อยู่ครบ ไม่มีงานค้าง ไม่มีใครถูกล็อก — ผู้ทดสอบเริ่มจากการเผยแพร่เวอร์ชันใหม่เอง |
| ไม่ใส่ (= `published`) | สคริปต์ตรวจ API (`docs/tools/legal-reacceptance-api-check.mjs`) | เหมือน baseline แล้วเผยแพร่ A0 และ A2 เวอร์ชัน `2.0` แบบลงนามซ้ำให้เลย ทั้งสองหน่วยงานถูกล็อกตั้งแต่ต้น |

รันซ้ำได้เสมอ ขอให้รัน `seed:demo` ก่อนทุกครั้ง: `seed:demo` ล้างหน่วยงาน ผู้ใช้ และการลงนามทั้งหมด แต่**ไม่ล้างเวอร์ชันเอกสาร**
เวอร์ชันที่เคยเผยแพร่ในการทดสอบรอบก่อนจึงยังอยู่ และ baseline ให้ลงนามเวอร์ชันที่ใช้อยู่ตอนนั้น บรรทัดสุดท้ายของ seed
บอกเวอร์ชันที่ใช้อยู่ (เช่น `A0=2.0 A1=1 A2=2.0 A3=1`) **ให้จดไว้ เพราะในเอกสารนี้เรียกค่านั้นว่า "เวอร์ชันเดิม"**
ส่วนเวอร์ชันใหม่ที่จะเผยแพร่ ตัวอย่างในเอกสารนี้ใช้ `3.0` ถ้าเคยใช้เลขนั้นแล้วให้ใช้เลขอื่น (ระบบรับข้อความอิสระ)

ไฟล์ .docx สำหรับอัปโหลดอยู่ที่ `backend/src/assets/legal-templates/A0.docx` … `A3.docx`

รหัสผ่านทุกบัญชี `bdi12345` · OTP อยู่ใน `docker compose logs delivery-worker` (ค้นคำว่า "รหัส OTP:")
อีเมลที่ระบบส่งดูได้ที่ `/console` → ประวัติการส่งอีเมล หรือใน log เดียวกัน
