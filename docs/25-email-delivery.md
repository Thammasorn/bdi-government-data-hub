# 25 — อีเมลทุกฉบับส่งผ่าน delivery worker

การ์ด Notion: **[Enhance] Send every email through the delivery worker** (Task Board, 2026-11-08) — requirement อยู่บนการ์ด
เอกสารนี้คือฉบับที่สร้างแล้ว

## 1. ก่อนและหลัง

| อีเมล | ก่อน | หลัง |
|---|---|---|
| คำเชิญ (ผู้ดูแลเชิญ, ส่งซ้ำ, เชิญกลับ, คำขอเปลี่ยนผู้แทน, ผู้มีอำนาจฯ ตอนผ่านด่านแรก) | inline จากคำขอ | outbox + secret เข้ารหัส |
| ลิงก์ตั้งรหัสผ่านใหม่ | inline | outbox + secret เข้ารหัส |
| รหัส OTP | inline | outbox + secret เข้ารหัส + ปลุก worker ทันที |
| อีเมลทดสอบของหน้าแก้เทมเพลต | inline | outbox (เนื้อหาที่กำลังแก้อยู่ในช่อง secret) |
| มอบหมายผู้เชี่ยวชาญ | inline | outbox (branch ของตัวเองใน `workers/render.ts`) |
| อีเมลแจ้งงานอื่นทั้งหมด | outbox | outbox (เหมือนเดิม) |
| สรุป error ถึงทีมดูแลระบบ | loop ของตัวเองใน worker | ไม่เปลี่ยน — ผู้รับไม่ใช่บัญชี และต้องส่งได้แม้ฐานข้อมูลล่ม |

ก่อนการ์ดนี้ SMTP สะดุดหนึ่งครั้ง = อีเมลหาย ไม่มี retry ไม่มีบันทึก ผู้ดูแลเห็นแค่ 500

## 2. secret ที่อีเมลต้องพก — `lib/outbox-secret.ts`

- คีย์ดิบ/โทเคน/รหัส อยู่ใน `notification_delivery.secret_payload` แบบ **AES-256-GCM** กุญแจคือ SHA-256 ของ `OUTBOX_SECRET_KEY`
  (env ไม่ใช่ฐานข้อมูล) รูปที่เก็บ `v1.<iv>.<tag>.<ciphertext>`
- **ถูกลบ** เมื่อแถวเป็น `SENT` / `CANCELLED` / `DEAD_LETTER` (ในคำสั่งเดียวกับที่เปลี่ยนสถานะ) และเมื่อเลย `secret_expires_at`
  (worker กวาดทุกรอบ ยกเลิกอีเมลด้วย `SECRET_EXPIRED`) — มีคำสั่งตาข่ายลบ secret ที่ค้างในแถวที่จบแล้วอีกชั้น
- อายุ: คำเชิญ = วันหมดอายุของคีย์ · ลิงก์ = ของลิงก์ · OTP = ของรหัส · อีเมลทดสอบ = 1 ชั่วโมง
- ถอดไม่ออก (กุญแจถูกหมุน แถวถูกแก้) → ยกเลิก `SECRET_UNREADABLE` และเก็บ error — ไม่ส่งของที่อาจผิด
- `OUTBOX_SECRET_KEY` ต้องตั้งบน production ทั้ง backend และ delivery-worker ค่าเดียวกัน (`openssl rand -base64 32`)

## 3. worker — `workers/delivery.ts`, `workers/render-system.ts`

- **ตรวจก่อนส่ง** แล้ว**ยกเลิก**ถ้าสิ่งที่อีเมลพาไปใช้ไม่ได้แล้ว: คีย์ถูกใช้/เพิกถอน/แทน/หมดอายุ (`INVITATION_NOT_PENDING`), ลิงก์ถูกใช้หรือแทน
  (`RESET_LINK_NOT_VALID`), OTP ถูกใช้หรือแทน (`OTP_NOT_VALID`), หน่วยงานถูกระงับ (`ORGANIZATION_FROZEN`)
- **ปลุกทันที**: `notifyUsers()` เรียก `pg_notify('outbox_wakeup')` ในธุรกรรม (ส่งตอน commit) worker `LISTEN` ด้วยการเชื่อมต่อ `pg`
  ของตัวเอง (Prisma ทำไม่ได้) หลุดแล้วต่อใหม่ทุก 5 วินาที รอบ 15 วินาทียังอยู่เป็นตาข่าย — วัดได้ OTP ถึงใน 0.66 วินาทีหลังกดเข้าสู่ระบบ
- batch เต็ม (20) → วนต่อทันทีไม่รอ
- **ความล้มเหลว** (`lib/delivery-errors.ts`):

| หมวด (`last_error_code`) | เกิดจาก | ทำอะไร | หน้าจอบอก | ใครแก้ |
|---|---|---|---|---|
| `SMTP_REJECTED` | 5xx ที่ `RCPT TO` / `DATA` | เลิกส่งทันที (`DEAD_LETTER`) | ไม่มีกล่องจดหมายนี้ — ตรวจอีเมลผู้รับ | ผู้ดูแลระบบ |
| `SMTP_AUTH` | `EAUTH`, 530/534/535/538 | ลองใหม่ตามรอบ | เข้าสู่เซิร์ฟเวอร์อีเมลไม่ได้ — แจ้งฝ่าย IT | ฝ่าย IT |
| `SMTP_UNREACHABLE` | timeout, ต่อไม่ได้ | ลองใหม่ตามรอบ | เซิร์ฟเวอร์อีเมลไม่ตอบ — ระบบลองใหม่เอง | ไม่ต้องทำ |
| `SEND_FAILED` | อื่น ๆ | ลองใหม่ตามรอบ | ส่งไม่สำเร็จ — ถ้ายังไม่ได้ให้แจ้งฝ่าย IT | ฝ่าย IT |

  `DEAD_LETTER` ทุกฉบับเป็น error (`delivery.dead-letter`) จึงขึ้นอีเมลสรุป error ของทีมดูแลระบบอยู่แล้ว (มีก่อนการ์ดนี้)

## 4. API

```
GET  /api/admin/deliveries            รายการ — ?state=failed|retrying|queued|sent|cancelled &type= &q=(อีเมลผู้รับ) &page &pageSize
GET  /api/admin/deliveries/:id        สถานะฉบับเดียว (ตัวติดตามในหน้าจอ)
POST /api/admin/deliveries/:id/resend เข้าคิวใหม่ — เฉพาะอีเมลที่ไม่พก secret (409 resend_elsewhere สำหรับคำเชิญ/ลิงก์, still_sending ถ้ายังในคิว)
GET  /api/auth/otp-delivery/:id       สถานะการส่ง OTP — ไม่ต้องล็อกอิน ตอบแค่ { state } เฉพาะแถว OTP อายุไม่เกิน 15 นาที
```

คำสั่งที่ส่งอีเมล (`POST /api/admin/invitations`, `…/resend`, `…/users/:id/reinvite`, `…/users/password-reset`,
`…/email-templates/:key/test-send`) คืน `deliveryId` · `POST /api/auth/login` และ `/login/resend-otp` คืน `otpDeliveryId`
รายการคำเชิญ (`/api/admin/invitations`), ผู้ใช้ (`includeInvited`) และหน้าผู้ใช้แนบ `emailDelivery` ต่อคีย์ หน้าผู้ใช้แนบ
`passwordResetDelivery` ด้วย จำนวนบน tile "อีเมลที่ส่งไม่สำเร็จ" คือ `deadLetters` ของ `/api/admin/summary` (นับเท่ากับ `state=failed`)

## 5. หน้าจอ

- **ตัวติดตาม** (`components/console/DeliveryTracker.tsx`) มุมขวาล่างของ /console — หลังเชิญ ส่งซ้ำ เชิญกลับ ส่งลิงก์ หรือส่งทดสอบ ติดตามฉบับนั้น
  ทุกวินาทีใน 10 วินาทีแรก แล้วทุก 3 วินาทีจนครบ 30 วินาที อยู่ข้ามการเปลี่ยนหน้า ปิดเอง
- **ป้ายในแถว** (`DeliveryChip`) — ตารางคำเชิญ หน้าสมาชิกและคำเชิญ หน้าผู้ใช้ (คีย์แต่ละใบ และลิงก์ตั้งรหัสผ่านล่าสุด)
- **ประวัติการส่งอีเมล** (`/console/email-deliveries`, เมนูตั้งค่าระบบ) — กรองสถานะ/ชนิด/อีเมล เหตุผลและผู้แก้ต่อแถว "ส่งอีกครั้ง" สำหรับ
  อีเมลทั่วไป "ไปที่คำเชิญ" / "ไปที่ผู้ใช้" สำหรับคำเชิญ/ลิงก์ (ต้องออกคีย์/ลิงก์ใหม่) tile บนหน้าภาพรวมลิงก์มาที่ `?state=failed`
- **หน้าเข้าสู่ระบบ** ถามสถานะ OTP ทุกวินาทีจนส่งถึงหรือครบ 30 วินาที ส่งไม่สำเร็จ → "ส่งรหัสไม่สำเร็จ กรุณากดส่งรหัสอีกครั้ง" และปุ่มขอรหัสใหม่กดได้ทันที
- แถว notification ของอีเมลระบบ (`SYSTEM_EMAIL_TYPES`) เกิดมาอ่านแล้วและไม่ขึ้นกระดิ่ง

## 6. ตรวจแล้ว (dev checkout slot 17, 2026-11-08)

- OTP ผ่าน worker ถึงใน 0.66 วินาที secret ถูกลบหลังส่ง เข้าสู่ระบบด้วยรหัสนั้นได้ · id อื่นที่ endpoint สถานะ OTP ได้ 404
- คำเชิญ/ลิงก์ตั้งรหัสผ่าน/อีเมลทดสอบผ่าน worker คีย์และลิงก์ในอีเมลใช้ได้จริง กระดิ่งไม่แสดงแถวของระบบ
- คำเชิญผู้มีอำนาจฯ ตอนผู้ประสานงานของ BDI ผ่านด่านแรก — เข้าคิวหลัง commit ส่งก่อน "ขอความเห็นชอบ" ที่รอ 59 วินาที ลำดับเหมือนเดิม
- มอบหมายผู้เชี่ยวชาญ — อีเมลฉบับเดียว จากเทมเพลตของมัน
- กับ SMTP ปลอม: ที่อยู่ที่ถูกปฏิเสธ → `DEAD_LETTER` ครั้งแรก เหตุผล "ไม่มีกล่องจดหมายนี้" secret ถูกลบ · login ไม่ผ่าน → `FAILED` เก็บ secret ไว้
  เหตุผล "แจ้งฝ่าย IT" แล้วส่งสำเร็จเมื่อ login กลับมาได้ · secret หมดอายุระหว่างรอ retry → `CANCELLED` `SECRET_EXPIRED` secret ถูกลบ
- ส่งอีกครั้งอีเมลทั่วไปได้แถวใหม่ที่ส่งสำเร็จ คำเชิญได้ 409 พร้อมทางไป
- เบราว์เซอร์ (`sit-evidence/delivery-worker-check.mjs`): ตัวติดตาม "ส่งแล้ว" / "ส่งไม่สำเร็จ" พร้อมเหตุผล, ป้ายในตารางคำเชิญ, tile → ประวัติ (กรองแล้ว),
  หน้าเข้าสู่ระบบบอก "ส่งรหัสไม่สำเร็จ"
- **ยังไม่ได้ทดสอบกับ Office 365 จริง**
