# 22 · ชุดเอกสารของคำขอ และหน้าตั้งค่าเอกสาร

การ์ด **Enhance Legal document management** (2026-10-10) — สองเรื่องที่ไปด้วยกัน: (1) คำขอถือเอกสารเวอร์ชันที่ตัวเองนำส่งไปตลอดเรื่อง
(2) BDI เพิ่ม เปิด/ปิดใช้ และออกเวอร์ชันของเอกสารเองจาก `/console` โดยไม่ต้อง deploy

## 1 · คำขอถือชุดเอกสารของตัวเอง

ก่อนหน้านี้ทุกจุดที่แสดง ลงนาม หรือ render เอกสารอ่าน "เวอร์ชันล่าสุดที่เผยแพร่" (`publishedDocuments()`) ฝ่ายกฎหมายจึงเปลี่ยนเอกสารใต้คำขอที่กำลัง
เดินอยู่ได้ — ผู้อนุมัติเห็นไฟล์คนละฉบับกับที่หน่วยงานนำส่ง และไฟล์ที่ดาวน์โหลดเปลี่ยนไปเองหลังลงนาม

**ตอนนี้** การนำส่งแต่ละครั้งบันทึกแถวลง `legal.request_document_snapshot` — คำขอไหน (`subject_type` + `subject_id`) นำส่งครั้งที่เท่าไร
(`submission_no`) ใช้เอกสารเวอร์ชันไหน (`legal_document_version_id`) ลำดับเท่าไร (`display_order`) และบังคับหรือไม่ (`is_required`) ทุกอย่างหลังจากนั้นอ่านจากที่นี่ผ่าน
**`documentsForRequest()`** ใน `lib/legal.ts` ซึ่งเป็นจุดอ่านเดียว: `requestDocuments()` (รายการ/ด่านลงนามของเส้นทางหน่วยงาน),
`GET /:id/legal-documents` ของเส้นทางชุดข้อมูล, ด่านตรวจตอนลงนาม และ `renderPlaceholderDocuments()` / `renderDatasetDocuments()`

| สถานะคำขอ | ชุดเอกสารที่เห็น |
|---|---|
| `DRAFT` / `RETURNED` | ชุดล่าสุดที่เผยแพร่ (เปลี่ยนตามเวลาได้ — หน่วยงานยังแก้ฟอร์มและสร้าง PDF ใหม่ได้) |
| นำส่งแล้ว (`SUBMITTED` … `CANCELLED`) | ชุดที่บันทึกตอนนำส่งครั้งล่าสุด ไม่เปลี่ยนต่อให้มีเวอร์ชันใหม่ เอกสารใหม่ หรือปิดใช้เอกสาร |
| นำส่งแล้วแต่ยังไม่มีแถว (ก่อน backfill) | ตกกลับไปใช้ชุดล่าสุดเหมือนเดิม ไม่พัง |

- **ส่งกลับแล้วนำส่งใหม่** ได้ชุดใหม่ (`submission_no` ถัดไป) ด้วยเวอร์ชันล่าสุด ณ ตอนนั้น ชุดเก่าเก็บเป็นประวัติ ไม่ลบ
- **`is_required` และ `display_order` ถูกบันทึกไปด้วย** — แอดมินสลับบังคับ/ไม่บังคับหรือจัดลำดับภายหลังต้องไม่เปลี่ยนชุดที่หน่วยงานเห็นไปแล้ว ส่วน `name_th` `shortname`
  `legal_notice` ยังอ่านจากเอกสารสด (เป็นถ้อยคำบนหน้าจอ ไม่ใช่เนื้อสัญญา)
- **การนำส่งปฏิเสธ 409 `documents_changed`** ถ้าฝ่ายกฎหมายเผยแพร่เวอร์ชันใหม่ของเอกสารที่มี placeholder หลังจากที่ผู้กรอกกดสร้าง PDF — เอกสารที่นำส่งต้องเป็นฉบับที่เขาเพิ่ง
  เห็น (`documentsAwaitingRender()`) กลับไปกดตรวจสอบข้อมูล/สร้าง PDF ใหม่แล้วนำส่งอีกครั้ง
- `legal_acceptance` ชี้เวอร์ชันอยู่แล้ว หลักฐานการลงนามจึงไม่เคยเปลี่ยน — สิ่งที่ปิดคือช่วงก่อนและรอบการลงนาม

### ขึ้น production

1. deploy `main` — `migrate deploy` สร้างตาราง ยังไม่มีผลต่อคำขอเดิม
2. **backfill** คำขอที่ค้างอยู่ (รายงานก่อน แล้วค่อยเขียน):

```bash
docker compose exec backend npm run backfill:document-snapshots:prod            # ดูอย่างเดียว ไม่เขียนอะไร
docker compose exec backend npm run backfill:document-snapshots:prod -- --write # เขียนจริง
```

รายงานบอกจำนวนคำขอต่อ scope ต่อสถานะ เวอร์ชันที่จะผูก และคำขอที่จะถือเวอร์ชันเก่ากว่าล่าสุด **ต่อฉบับ** ใช้เวอร์ชันที่คำขอนั้นเคยรับไว้ใน `legal_acceptance` ถ้ามี
ไม่มีก็ใช้ฉบับที่เผยแพร่อยู่ตอนนี้ (ย้อนรู้ไม่ได้ว่าหน่วยงานเห็นอะไรตอนกดนำส่ง) รันซ้ำได้ — คำขอที่มี snapshot แล้วถูกข้าม

## 2 · หน้าตั้งค่าเอกสาร (`/console`)

หมวด **ตั้งค่าเอกสาร** (เดิม "ตั้งค่าระบบ"): เอกสารข้อตกลง · ตัวเลือกเอกสารชุดข้อมูล (เดิม "ตัวเลือกในแบบฟอร์ม") · เอกสารดาวน์โหลด · ตัวแปรที่ใช้ใน template

- **รายการ** `/console/legal-documents` — สองหัวข้อ (เอกสารของคำขอลงทะเบียนหน่วยงาน / ของคำขอส่งชุดข้อมูล) แต่ละแถวมีแค่ชื่อ อัปโหลดฉบับใหม่ และแก้ไข
  ปุ่ม **เพิ่มเอกสาร** ต่อท้ายลำดับเสมอ เอกสารที่ปิดใช้ยังอยู่ในรายการ (จางลง ท้ายหัวข้อ)
- **แก้ไข** `/console/legal-documents/:code` — ข้อมูลเอกสาร (`name_th` `short_name` `legal_notice` `is_required`) · เปิด/ปิดใช้ · เวอร์ชันที่ใช้อยู่ ·
  **Version History** (แบ่งหน้า ดูตัวอย่าง PDF ก่อน/หลัง render ดาวน์โหลด .docx "ใช้เวอร์ชันนี้" สำหรับฉบับร่าง "เผยแพร่อีกครั้ง" สำหรับฉบับที่ถูกแทนที่ — ทั้งสองพลิกแถวเดิมกลับเป็น `PUBLISHED` ไม่ออกเวอร์ชันใหม่)
- **modal อัปโหลด** (ใช้ทั้งเวอร์ชันใหม่และเอกสารใหม่) — เลือกไฟล์ → ระบบตรวจชื่อตัวแปร → ปุ่ม **ดูตัวอย่างก่อน render** (ตามที่พิมพ์ เห็น `{{…}}`) และ **หลัง render**
  (เติมข้อมูลตัวอย่างที่เป็นทางการ ไฮไลต์เหลืองเฉพาะส่วนที่ระบบเติม) → ติ๊ก **ใช้ทันที** (ค่าตั้งต้น) → ยืนยัน ไฟล์ไม่ถูกเก็บจนกดยืนยัน
- **ใช้ทันที** ออก = เก็บเป็น `DRAFT` ไม่มีผลกับใคร เผยแพร่ภายหลังด้วย "ใช้เวอร์ชันนี้" · เอกสารใหม่ที่ไม่ติ๊ก = สร้างแต่ปิดใช้ (`legal_document.status = DRAFT`)
- **ตัวแปรที่ใช้ใน template** `/console/template-variables` — หน้าอ้างอิง (เดิมเป็น modal) กรองตามชนิดเอกสาร คัดลอกชื่อได้
- ข้อมูลตัวอย่างของ preview อยู่ใน `lib/legal-preview.ts` (หน่วยงาน/ผู้ลงนาม/ชุดข้อมูลสมมติ ค่าคงที่) — เปลี่ยนที่นั่นที่เดียว

### เปิด/ปิดใช้ และกติกาต่อหมวด

เปิดใช้ = `legal_document.status = ACTIVE` · ปิดใช้ = `RETIRED` (หรือ `DRAFT` ถ้ายังไม่เคยเปิด) ย้อนกลับได้ ปิดแล้วผู้ที่นำส่ง**จากนี้ไป**ไม่ได้เอกสารนั้น คำขอที่นำส่งไปแล้วยังถือชุดเดิม

แต่ละหมวด (`application_scope`) ต้องมี **(1)** เอกสารที่เปิดใช้และมีเวอร์ชัน `PUBLISHED` อย่างน้อย 1 ฉบับ และ **(2)** อย่างน้อย 1 ฉบับในนั้นเป็น `is_required` — ตรวจใน transaction ที่
`SELECT … FOR UPDATE` แถวของหมวดไว้ (แอดมินสองคนปิดคนละฉบับพร้อมกันต้องรอกัน) และตรวจหลังเขียน เฉพาะเมื่อการเปลี่ยนครั้งนี้ทำให้กติกาที่เคยจริงพัง
ตอบ 409 พร้อมเหตุผลภาษาไทยที่บอกทางออก:

| `error` | เมื่อไร |
|---|---|
| `last_active_document` | ปิดใช้ฉบับที่เป็นฉบับเดียวที่ผู้ใช้เห็นของหมวด |
| `no_required_document` | ปิดใช้ หรือเปลี่ยนเป็นไม่บังคับ ซึ่งเป็นฉบับบังคับสุดท้ายของหมวด |
| `no_published_version` | เปิดใช้เอกสารที่ยังไม่มีเวอร์ชันเผยแพร่ (ผู้ใช้จะไม่เห็นอะไรเลย) |

หน้าแก้ไขปิดปุ่มพร้อมข้อความเดียวกันก่อนกด แต่ด่านจริงคือ API

**เผยแพร่เวอร์ชันไม่เปลี่ยนสถานะของเอกสาร** (`publishVersion()` เดิมเปิดใช้ให้เงียบ ๆ) — เอกสารที่ปิดใช้อัปโหลดและเผยแพร่เวอร์ชันได้โดยไม่ถูกเปิดกลับ `seed:masters` ที่สร้างเอกสารเป็น `DRAFT`
เปิดใช้เองหลังเผยแพร่เวอร์ชันแรก และ**ไม่เขียนทับ** `name_th` `shortname` `legal_notice` `display_order` อีกแล้ว (เดิมอยู่ใน `update` ของ upsert — ตอนนี้เป็นของหน้า /console)

## 3 · บทบาท `BDI_LEGAL_OFFICER`

เห็นเฉพาะหมวด "ตั้งค่าเอกสาร" ของ `/console` (เมนู "ตั้งค่าเอกสาร" บนแถบหัว) ทำได้เท่าผู้ดูแลระบบในหมวดนั้น: `/api/admin/legal-documents`, `/template-variables`,
`/dataset-choices`, `/public-documents` — guard คือ `requireDocumentAdmin` ใน `middleware/auth.ts` ส่วนที่เหลือของ `/api/admin/*` ตอบ 403 และ `/console` อื่นแสดงการ์ดบอกว่าเป็นของผู้ดูแลระบบ
ไม่มีขั้นอนุมัติแยกก่อนเผยแพร่ (ตัดสินใจกับ BDI 2026-10-10)

## 4 · API ที่เพิ่ม/เปลี่ยน

| | |
|---|---|
| `POST /api/admin/legal-documents` | สร้างเอกสาร (multipart: `scope` `documentCode` `nameTh` `isRequired` `shortname` `legalNotice` `apply` `file`) — รหัสซ้ำ/ชื่อสั้นซ้ำ 409 `conflict` |
| `PATCH …/legal-documents/:code` | เพิ่ม `nameTh` และ `isActive` |
| `GET …/legal-documents` | เพิ่ม `isActive` `hasPublishedVersion` `activeVersion` `draftVersionCount` `versionCount` |
| `GET …/legal-documents/:code/versions?page&pageSize` | ประวัติเวอร์ชันแบ่งหน้า |
| `POST …/legal-documents/:code/versions` | เพิ่ม `apply` (ค่าตั้งต้น true; false = `DRAFT`) |
| `POST …/versions/:versionId/activate` | ใช้ฉบับร่าง (`DRAFT`) หรือฉบับที่ถูกแทนที่ (`SUPERSEDED`) เป็นฉบับที่เผยแพร่ — แถวเดิม ไม่สร้างเวอร์ชันใหม่ (`…/restore` เหมือนกัน แต่รับเหตุผล) |
| `GET …/versions/:versionId/preview?mode=raw\|rendered` | PDF ตัวอย่างของเวอร์ชันที่เก็บไว้ |
| `POST …/legal-documents/inspect` · `…/preview` | ตรวจ / ดูตัวอย่างไฟล์ที่เพิ่งเลือก (ยังไม่เก็บ) — multipart `file` `scope` (`mode`) |
| `GET /api/admin/template-variables` | รายการตัวแปรจัดกลุ่ม พร้อม scope ที่ใช้ได้ |

| `DELETE …/versions/:versionId` | ลบเวอร์ชันถาวร — ไม่ใช่ฉบับที่ใช้อยู่ ไม่มีคำขอผูก (`request_document_snapshot`) ไม่มีหลักฐานการยอมรับ (`legal_acceptance`) ไม่งั้น 409 `version_active` · `version_in_use` · `version_accepted` |
| `DELETE …/legal-documents/:code` | ลบเอกสารทั้งฉบับถาวร (§6) |

audit: การสร้าง/แก้/เปิด-ปิดใช้/ใช้ฉบับร่าง/ลบ เขียน `LEGAL_DOCUMENT_CHANGED` (`metadata.operation` = CREATE · UPDATE · ACTIVATE · DEACTIVATE · VERSION_ACTIVATED · VERSION_DELETED · DELETE)
การอัปโหลดยังเป็น `LEGAL_DOCUMENT_PUBLISHED`

## 5 · ที่ยังไม่ได้ทำ

- `DATASET_REQUEST` (คำขอใช้ข้อมูล) ยังไม่มีเส้นทาง — `request_document_snapshot` รองรับ `subject_type` นั้นแล้ว แต่ `documentsForRequest()` รู้จักแค่สองเส้นทางที่มีอยู่
- ยังไม่มีปุ่มจัดลำดับเอกสาร (ต่อท้ายเสมอ) · ลบได้เฉพาะเวอร์ชัน/เอกสารที่ไม่เคยมีใครใช้ (§6) — ที่ใช้แล้วปิดใช้หรือถูกแทนที่เท่านั้น
- Postman collection (`L1`–`L4`) ยังไม่มีคำขอของ endpoint ใหม่

## 6 · ลบเอกสารที่ไม่เคยมีใครใช้

การ์ด **Delete unused legal document** (2026-10-28) — ปุ่ม **ลบ** ในกล่อง "สถานะการใช้งาน" ของหน้าแก้ไข ข้างปุ่มเปิด/ปิดใช้ ใช้ปุ่มและกล่องยืนยันชุดเดียวกับลบเวอร์ชัน
(ยืนยันครั้งเดียว ไม่ต้องพิมพ์ชื่อหรือรหัสผ่าน) เพราะกติกาเดียวกัน: ของที่ไม่เคยมีใครใช้ไม่มีหลักฐานให้เสีย ลบไม่ได้ปุ่มก็ยังเห็น จาง และ tooltip บอกเหตุผล

`DELETE /api/admin/legal-documents/:code` (`requireDocumentAdmin` — ผู้ดูแลระบบและ `BDI_LEGAL_OFFICER` เหมือนลบเวอร์ชัน) ลบได้เมื่อ**ทุกข้อ**จริง ไม่งั้น 409:

| `error` | เมื่อไร |
|---|---|
| `seeded_document` | A0–A4 (`SEEDED_DOCUMENT_CODES` ใน `lib/legal.ts`) — `seed:masters` upsert ทุกรอบ ลบแล้วจะถูกสร้างกลับ seed ตรวจว่ารายการตรงกัน |
| `document_active` | ยังเปิดใช้อยู่ — คู่กับ "ลบฉบับที่ใช้อยู่ไม่ได้" ของเวอร์ชัน ปิดใช้ (ซึ่งตรวจกติกาต่อหมวดไว้แล้ว) ก่อน |
| `document_in_use` | เวอร์ชันไหนก็ได้ของเอกสารมีแถวใน `request_document_snapshot` = คำขอเคยนำส่งพร้อมเอกสารนี้ (สถานะใดก็ได้ รวม RETURNED) |
| `document_accepted` | เวอร์ชันไหนก็ได้มีแถวใน `legal_acceptance` |

- ตรวจและลบใน transaction เดียวที่ `lockScope()` (ล็อกเดียวกับเปิด/ปิดใช้) ลบเวอร์ชัน → เอกสาร → แถวไฟล์ แล้วจึงลบ blob (ลบ blob ไม่ได้ไม่ย้อน)
- คำขอที่นำส่งพร้อมกันแล้วเขียน snapshot ทัน: การลบเวอร์ชันรอ lock ของ FK แล้วชน `request_document_snapshot_legal_document_version_id_fkey` → ตอบ 409 `document_in_use` ไม่มี snapshot ชี้เวอร์ชันที่หายไป (ทดสอบแล้วด้วย transaction ค้าง)
- **PDF ที่คำขอฉบับร่างสร้างไว้** (`attachment.legal_document_version_id` ชี้เวอร์ชันของเอกสารนี้ ไม่มี FK) ถูกลบไปด้วย ฉบับร่างนั้นแค่ไม่เห็นเอกสารนี้อีก เหมือนตอนปิดใช้
- ลบแล้วรหัสและชื่อสั้นว่างให้ใช้ใหม่ได้ audit `LEGAL_DOCUMENT_CHANGED` `operation = DELETE` เก็บ id รหัส เลขเวอร์ชัน และจำนวนไฟล์
- `GET /api/admin/legal-documents` เพิ่ม `usageCount` (คำขอไม่ซ้ำ ทุกเวอร์ชันรวม) `acceptanceCount` `requestFileCount` `isSeeded` ต่อเอกสาร — หน้าแก้ไขใช้บอกเหตุผลและจำนวนไฟล์ในกล่องยืนยัน
