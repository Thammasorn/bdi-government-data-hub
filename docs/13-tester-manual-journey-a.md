# เล่ม A — ผู้ดูแลระบบสร้างหน่วยงานและเชิญผู้ใช้

**เขียนสำหรับผู้ดูแลระบบ** ขั้นตอนนี้ **ไม่มีหน้าจอ** โดยตั้งใจตามข้อกำหนด — ทำผ่านการเรียก API
ด้วยคำสั่ง `curl` หรือโปรแกรม Postman ส่วนครึ่งหลังของเล่ม (ข้อ 5 เป็นต้นไป) เป็นสิ่งที่
**ผู้ถูกเชิญ** ทำบนหน้าเว็บ ผู้ถูกเชิญอ่านเฉพาะข้อ 5–7 ก็พอ

> ต้องอ่าน [เล่มภาพรวม](12-tester-manual-overview.md) ก่อน

---

## 0. เตรียมตัว

ต้องรู้สองอย่าง

| สิ่งที่ต้องรู้ | หาได้จากไหน | ตัวอย่างในเครื่องทดสอบ |
| --- | --- | --- |
| **ที่อยู่ของ API** | ผู้ติดตั้งระบบ | `http://localhost:4400` |
| **รหัสลับของผู้ดูแล** (`ADMIN_API_TOKEN`) | ไฟล์ `.env` ของ checkout นั้น | `dev-admin-token-change-me` |

ทุกคำสั่งในเล่มนี้ต้องแนบหัวข้อ `x-admin-token` เสมอ ถ้าไม่แนบหรือใส่ผิดจะได้

```json
{"error":"unauthenticated","message":"x-admin-token ไม่ถูกต้อง"}
```

ตั้งค่าตัวแปรไว้ก่อนเพื่อไม่ต้องพิมพ์ซ้ำ

```bash
cd /path/to/checkout          # โฟลเดอร์ที่มีไฟล์ docker-compose.yml
export API=http://localhost:4400
export T=$(grep ^ADMIN_API_TOKEN= .env | cut -d= -f2)
```

> มี Postman collection พร้อมใช้อยู่แล้วที่ `docs/bdi-admin-portal.postman_collection.json`
> พร้อมไฟล์ environment สามแบบข้าง ๆ กัน — นำเข้าทั้งคู่แล้วเลือก environment มุมขวาบนก่อนยิง

## 1. สร้างหน่วยงานไว้ล่วงหน้า

ผู้ดูแลระบบสร้างแถวของหน่วยงานไว้ก่อน แล้วผูกคำเชิญเข้ากับหน่วยงานนั้น ข้อมูลที่กรอกไว้ตรงนี้
จะถูก **เติมให้อัตโนมัติ** ในแบบฟอร์มของผู้ใช้ตอนเขาเริ่มลงทะเบียน (เล่ม B)

```bash
curl -s -X POST $API/api/admin/organizations \
  -H "x-admin-token: $T" -H 'Content-Type: application/json' \
  -d '{
    "organizationCode": "MOT-DEMO-01",
    "nameTh": "สำนักงานปลัดกระทรวงคมนาคม",
    "nameEn": "Office of the Permanent Secretary, Ministry of Transport",
    "organizationType": "ส่วนราชการ",
    "addressLine": "38 ถนนราชดำเนินนอก",
    "province": "กรุงเทพมหานคร",
    "district": "ป้อมปราบศัตรูพ่าย",
    "subdistrict": "วัดโสมนัส",
    "postalCode": "10100",
    "phone": "022835000",
    "email": "saraban@mot.go.th",
    "websiteUrl": "https://www.mot.go.th"
  }'
```

ตอบกลับ `201` พร้อม `organization.id` — **เก็บ id นี้ไว้ ใช้ต่อในข้อ 2**

```json
{"organization":{"id":"8dfc51f7-582f-45bf-bd14-31e7c7bdf676",
  "organizationCode":"MOT-DEMO-01","status":"PENDING_REGISTRATION", … }}
```

### กติกาที่ต้องรู้

| เรื่อง | รายละเอียด |
| --- | --- |
| ช่องที่บังคับ | **`organizationCode` และ `nameTh` เท่านั้น** ที่เหลือเว้นได้ทั้งหมด |
| `organizationCode` | ผู้ดูแลกำหนดเอง ระบบไม่สร้างให้ · ห้ามซ้ำกับหน่วยงานอื่น (ซ้ำได้ `409 code_exists`) |
| สถานะเริ่มต้น | `PENDING_REGISTRATION` — จะเป็น `ACTIVE` ก็ต่อเมื่อผ่านเล่ม B ครบทุกด่าน |
| ที่อยู่ | ส่งเป็น **ชื่อ** ไม่ใช่รหัส และ **ชื่อต้องตรงกับในระบบ** ("ดุสิต" ไม่ใช่ "เขตดุสิต") ชื่อที่เทียบไม่ได้จะตอบ `400` พร้อมบอกช่องที่ผิด |
| รหัสไปรษณีย์ | ถ้ากรอกจังหวัด/อำเภอ/ตำบลครบแล้วไม่ต้องส่ง ระบบเติมให้เอง |

### ดูและแก้ไขภายหลัง

```bash
curl -s "$API/api/admin/organizations?q=คมนาคม"     -H "x-admin-token: $T"   # ค้นหา
curl -s "$API/api/admin/organizations?status=ACTIVE" -H "x-admin-token: $T"   # กรองสถานะ
curl -s "$API/api/admin/organizations/<id>"          -H "x-admin-token: $T"   # รายละเอียด
```

`GET /api/admin/organizations/<id>` คืนทั้งข้อมูลหน่วยงาน **คำขอจดทะเบียน** และ **คำเชิญ**
ของหน่วยงานนั้นมาในคำตอบเดียว ใช้ตรวจว่าคำเชิญไปถึงใครและถูกใช้ไปหรือยัง

แก้ไขเฉพาะช่องที่ต้องการ (ช่องที่ไม่ส่งมา = ไม่แตะ, ส่ง `null` = ล้างค่า)

```bash
curl -s -X PATCH $API/api/admin/organizations/<id> \
  -H "x-admin-token: $T" -H 'Content-Type: application/json' \
  -d '{"phone":"022835050"}'
```

> **การแก้ไขหลังผู้ใช้เปิดแบบฟอร์มไปแล้ว จะไม่ไปถึงแบบฟอร์มของเขา** เพราะระบบคัดลอกข้อมูลไป
> ตั้งแต่ตอนเขาเริ่มกรอก (ถ้าเขียนทับจะไปลบสิ่งที่ผู้ใช้พิมพ์ไว้) กรณีนี้คำตอบจะแนบ
> `warning.code = "registration_in_progress"` พร้อมเลขที่คำขอมาเตือน — ต้องแจ้งผู้ใช้ให้แก้ในฟอร์มเอง

## 2. ส่งคำเชิญให้ผู้ใช้

```bash
curl -s -X POST $API/api/admin/invitations \
  -H "x-admin-token: $T" -H 'Content-Type: application/json' \
  -d '{
    "email": "somchai.tester@mot.go.th",
    "role": "ORGANIZATION_USER",
    "cid": "1234567890121",
    "organizationId": "8dfc51f7-582f-45bf-bd14-31e7c7bdf676"
  }'
```

ตอบกลับ `201`

```json
{"activationKeyId":"c517f24a-…","userAccountId":"06d5c8b2-…",
 "email":"somchai.tester@mot.go.th","role":"ORGANIZATION_USER",
 "roleLabel":"ผู้ดำเนินการของหน่วยงาน","organizationId":"8dfc51f7-…",
 "expiresAt":"2026-08-24T16:32:52.176Z"}
```

### รายละเอียดของแต่ละช่อง

| ช่อง | บังคับ | รายละเอียด |
| --- | --- | --- |
| `email` | ✅ | อีเมลผู้ถูกเชิญ · ห้ามซ้ำกับบัญชีที่มีอยู่แล้ว |
| `role` | ✅ | หนึ่งค่าจาก `BDI_OFFICER` · `BDI_FINAL_APPROVER` · `BDI_DATASET_SPECIALIST` · `BDI_LEGAL_OFFICER` · `SYSTEM_ADMINISTRATOR` · `ORGANIZATION_USER` · `ORGANIZATION_APPROVER` |
| `cid` | ✅ **ทุกบทบาท** | เลขบัตรประชาชน 13 หลัก · ต้องผ่านการตรวจหลักสุดท้าย · **เป็นเลขที่จะถูกนำไปเทียบกับ ThaiD ตอนเปิดใช้งานบัญชี** |
| `organizationId` | ไม่บังคับ | ผูกกับหน่วยงานที่สร้างไว้ในข้อ 1 · **ถ้าเว้นไว้** ระบบจะสร้างหน่วยงานเปล่าชื่อ "หน่วยงานใหม่" กับคำขอฉบับร่างรอไว้ให้แทน |

> **API จงใจไม่คืน token กลับมา** — ลิงก์เปิดใช้งานอยู่ในอีเมลเท่านั้น
> ถ้าเชิญอีเมลเดิมซ้ำ คำเชิญใบเก่าจะถูกยกเลิกอัตโนมัติ เหลือใช้ได้ใบเดียวเสมอ
> ลิงก์มีอายุ **7 วัน**

### ข้อผิดพลาดที่พบบ่อยและความหมาย

| สถานะ | `error` | หมายความว่า |
| --- | --- | --- |
| `400` | `validation` | มีช่องกรอกผิด ดูใน `fields` ว่าช่องไหน เช่น `{"cid":"เลขบัตรประชาชนไม่ถูกต้อง"}` |
| `401` | `unauthenticated` | `x-admin-token` ผิดหรือไม่ได้ส่งมา |
| `409` | `exists` | อีเมลนี้มีบัญชีในระบบแล้ว |
| `409` | `cid_exists` | **เลขบัตรนี้เป็นของบัญชีอื่นแล้ว** — หนึ่งเลขบัตรมีได้หนึ่งบัญชี ข้อความจะบอกด้วยว่าเป็นของอีเมลใด |

ตัวอย่างคำตอบของ `cid_exists` (ข้อความบอกวิธีแก้ให้ครบ)

```json
{"error":"cid_exists","message":"เลขบัตรประชาชนนี้เป็นของบัญชี somchai.tester@mot.go.th อยู่แล้ว —
 หนึ่งเลขบัตรมีได้หนึ่งบัญชี ถ้าต้องการส่งคำเชิญให้คนเดิมอีกครั้ง ให้เชิญอีเมลนั้นซ้ำ
 ระบบจะออกคีย์ใบใหม่และยกเลิกใบเก่าให้ ถ้าครั้งแรกกรอกอีเมลผิด ต้องแก้อีเมลของบัญชีนั้นก่อน"}
```

## 3. ดู ยกเลิก และลบคำเชิญ

```bash
curl -s $API/api/admin/invitations -H "x-admin-token: $T"                    # รายการทั้งหมด
curl -s -X POST $API/api/admin/invitations/<id>/revoke -H "x-admin-token: $T" # ยกเลิก
curl -s -X DELETE $API/api/admin/invitations/<id> -H "x-admin-token: $T"      # ลบ
```

**`revoke` กับ `DELETE` ต่างกันมาก — เลือกให้ถูก**

| คำสั่ง | ทำอะไร | ใช้เมื่อไร |
| --- | --- | --- |
| `revoke` | ยกเลิกเฉพาะ *ลิงก์* · **บัญชียังอยู่** และยังจองอีเมลกับเลขบัตรไว้ | ส่งลิงก์ผิดคน แต่ข้อมูลบัญชีถูกแล้ว |
| `DELETE` | ลบลิงก์ **และลบบัญชีทิ้ง** ถ้าบัญชีนั้นเกิดขึ้นเพราะคำเชิญใบนี้เท่านั้น | **กรอกอีเมลหรือเลขบัตรผิด** และต้องการนำค่าเดิมกลับมาใช้ใหม่ |

`DELETE` จะลบบัญชีให้ก็ต่อเมื่อบัญชีนั้นยัง `PENDING` · ไม่มีคีย์ใบอื่น · ไม่มีบทบาท ·
ไม่มีงานตรวจสอบที่ถูกมอบหมาย · ไม่เคยลงนามหรือยอมรับเงื่อนไข เงื่อนไขไม่ครบเมื่อไรจะลบเฉพาะ
คำเชิญ พร้อมบอกว่าอะไรเป็นตัวขวาง และ **บัญชีที่ `ACTIVE` แล้วตอบ `409`** เสมอ

ตัวอย่างคำตอบของ `DELETE` ที่ลบบัญชีให้ด้วย

```json
{"ok":true,
 "removed":{"activationKeyId":"3ad5faff-…",
   "userAccount":{"email":"typo.person@mot.go.th","cid":"1101700207994"},
   "organization":{"organizationCode":"ORG-2026-0007"},
   "registrationRequest":{"requestNumber":"ORG-REG-2026-0007"}},
 "message":"ลบคำเชิญและบัญชี typo.person@mot.go.th แล้ว — อีเมลและเลขบัตรประชาชนนี้ใช้เชิญใหม่ได้"}
```

## 4. หาลิงก์เปิดใช้งานบัญชี

**เครื่องที่ส่งอีเมลจริง** — ผู้ถูกเชิญเปิดอีเมลแล้วกดปุ่มในอีเมลได้เลย

**เครื่องทดสอบที่ไม่ส่งอีเมลจริง** — ผู้ดูแลระบบดึงลิงก์จากบันทึกการทำงาน

```bash
docker compose logs backend --tail 200 \
  | grep -A2 'ถึง: somchai.tester@mot.go.th' | grep 'ลิงก์:'
```

จะได้บรรทัดหน้าตาแบบนี้ ส่งให้ผู้ถูกเชิญ

```
[mail:dry-run] ลิงก์: http://localhost:3400/activate?token=OGLMC2fN8M9SQvDY4XukgyEMI338-xqmStKACR1TTTY
```

## 5. ผู้ถูกเชิญยืนยันตัวตนด้วย ThaiD

> ตั้งแต่ข้อนี้เป็นต้นไปเป็นการทำบนหน้าเว็บ **ผู้ถูกเชิญทำเอง** ไม่ต้องใช้คำสั่งใด ๆ

เปิดลิงก์ที่ได้รับ จะเห็นหน้านี้

![หน้ายืนยันตัวตนด้วย ThaiD](images/manual/a01-activate-thaid.png)

หน้าจอบอกล่วงหน้าว่าระบบจะเทียบเลขบัตรที่ได้จาก ThaiD กับเลขที่เจ้าหน้าที่บันทึกไว้
และโชว์ **4 ตัวท้าย** ให้ดูว่าเป็นบัตรใบไหน กด **ยืนยันตัวตนด้วย ThaiD**

ระบบจะพาไปที่หน้าของกรมการปกครอง

![หน้ายืนยันตัวตนของ ThaiD บนระบบทดสอบ](images/manual/a02-thaid-sandbox.png)

| ใช้ระบบทดสอบของกรมการปกครอง | ใช้ระบบจริง |
| --- | --- |
| **แก้เลขประจำตัวประชาชนในช่องได้** แล้วกด **ยืนยัน** | สแกน QR ด้วยแอป ThaiD บนมือถือ |

**ลองผิดได้และควรลอง:** ใส่เลขบัตรที่ไม่ตรงกับที่เจ้าหน้าที่บันทึกไว้ ระบบจะปฏิเสธ
**และยกเลิกลิงก์ทิ้งทันที** เปิดลิงก์เดิมซ้ำจะขึ้นว่า "ลิงก์คำเชิญนี้ถูกยกเลิกแล้ว"
ต้องขอลิงก์ใหม่ — เป็นพฤติกรรมที่ถูกต้องตามข้อกำหนดด้านความปลอดภัย

> เข้าหน้านี้จากหน้าเข้าสู่ระบบก็ได้ — กด **กรอก Activation Key** แล้ววางคีย์ที่ได้จากอีเมล

## 6. ตั้งรหัสผ่านและเปิดใช้งานบัญชี

ยืนยันตัวตนผ่านแล้วจะกลับมาที่หน้า **สร้างบัญชีผู้ใช้**

![หน้าสร้างบัญชีผู้ใช้ พร้อมข้อความแจ้งข้อผิดพลาดใต้ช่องรหัสผ่าน](images/manual/a03-activate-validation.png)

1. ช่อง **อีเมล** ถูกล็อกไว้แก้ไม่ได้ (กันคำเชิญถูกใช้ผิดคน)
2. เลือก **คำนำหน้า** แล้วกรอก **ชื่อ / นามสกุล**
   (ถ้า ThaiD ส่งชื่อกลับมาด้วย ระบบจะเติมให้ก่อน — ขึ้นกับสิทธิ์ที่ได้รับจากกรมการปกครอง)
3. กรอก **เบอร์โทรศัพท์** — ขึ้นต้นด้วย `0` และมี 9–10 หลัก
4. ตั้ง **รหัสผ่าน** — อย่างน้อย 8 ตัว มีทั้งตัวอักษรและตัวเลข
5. กด **เปิดใช้งานบัญชี**

ภาพด้านบนคือตัวอย่างของการใส่รหัสผ่านสั้นเกินไป — ข้อความสีแดงจะขึ้นใต้ช่องที่มีปัญหา
ลองผิดดูก่อนได้

**เสร็จแล้วระบบพาเข้าหน้าแรกให้อัตโนมัติ ไม่ต้องเข้าสู่ระบบอีกรอบ**

![หน้าแรกของผู้ดำเนินการหลังเปิดใช้งานบัญชี](images/manual/a08-home-after-login.png)

หน้าแรกบอกชื่อหน่วยงานที่คุณสังกัด สถานะ **อยู่ระหว่างลงทะเบียน** และมีปุ่ม
**กรอกแบบฟอร์มลงทะเบียนหน่วยงาน** ซึ่งเป็นจุดเริ่มต้นของ [เล่ม B](14-tester-manual-journey-b.md)

> ลิงก์คำเชิญ **ใช้ได้ครั้งเดียว** เปิดซ้ำจะขึ้นว่า "ลิงก์คำเชิญนี้ถูกใช้ไปแล้ว"

## 8. รายการทดสอบของเล่ม A

ติ๊กเมื่อทดสอบผ่าน

- [ ] สร้างหน่วยงานด้วยข้อมูลครบ → ได้ `201` และสถานะ `PENDING_REGISTRATION`
- [ ] สร้างหน่วยงานด้วยรหัสหน่วยงานซ้ำ → ได้ `409 code_exists`
- [ ] สร้างหน่วยงานด้วยชื่ออำเภอผิด (เช่น "เขตดุสิต") → ได้ `400` พร้อมชื่อช่องที่ผิด
- [ ] เชิญผู้ใช้พร้อม `organizationId` → ได้ `201`
- [ ] เชิญด้วยเลขบัตรที่ใช้ไปแล้ว → ได้ `409 cid_exists` พร้อมบอกอีเมลเจ้าของเดิม
- [ ] เชิญด้วยเลขบัตรมั่ว (เช่น `1111111111111`) → ได้ `400 validation`
- [ ] เรียก API โดยไม่ใส่ `x-admin-token` → ได้ `401`
- [ ] `revoke` คำเชิญ แล้วเปิดลิงก์เดิม → ใช้ไม่ได้
- [ ] `DELETE` คำเชิญของบัญชีที่ยังไม่เปิดใช้งาน → ลบบัญชีให้ด้วย และเชิญอีเมลเดิมซ้ำได้
- [ ] `DELETE` คำเชิญของบัญชีที่เปิดใช้งานแล้ว → ได้ `409`
- [ ] เปิดใช้งานบัญชีด้วยเลขบัตร **ตรงกัน** → เข้าระบบได้
- [ ] เปิดใช้งานบัญชีด้วยเลขบัตร **ไม่ตรงกัน** → ถูกปฏิเสธ และลิงก์เดิมใช้ไม่ได้อีก
- [ ] ตั้งรหัสผ่านสั้นกว่า 8 ตัว → มีข้อความสีแดงใต้ช่อง
- [ ] เปิดลิงก์คำเชิญซ้ำหลังใช้ไปแล้ว → ขึ้นว่าถูกใช้ไปแล้ว
- [ ] เข้าสู่ระบบด้วยรหัสผ่าน + OTP ได้
- [ ] เข้าสู่ระบบด้วย ThaiD ได้
